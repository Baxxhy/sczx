# 数据结构、权限与纠正

2026-11-10，v1。

新增0012_learning_memory，仅创建learning_memory_changes追加表。现有来源表可直接聚合，因此不增加证据副本、掌握快照、推荐任务或缓存表，也不修改历史快照。

新表字段：id、student_id、actor_id、source_event_id、knowledge_id、kind、request_key、details、created_at。actor+request_key唯一，时间为程序UTC微秒。details保留原事实/原判断、修订内容、理由、目标与请求摘要；新版修订另含原状态快照。旧事实不覆盖。

操作种类：学生correction_request、snooze；教师knowledge_correction、observation、review_required、review_content。学生纠正为请求，不自动改为事实；教师关联纠正才叠加到后续聚合。关联请求可以被教师修订记录引用。旧/新知识点下均显示相关审计。

接口：

- GET /api/memory：学生本人总览；教师必须指定有当前成员授权的学生，可用classId限定班级。
- POST /api/memory/changes：追加操作，必须带expectedRevision及requestKey；冲突409，不覆盖用户输入。

教师读取仅限当前有权限的班级与本人发布的任务来源。跨班学生不会因此暴露其他教师班级或个人独立错题。移出学生仍能读取自己的历史，教师学习记忆聚合按当前成员授权检查；原有历史任务页面沿用先前权限。

并发修订按学生账号串行检查，重新读取最新事实和审计版本，同请求幂等重放，不同的过期决定拒绝。原表保持只读，教师纠正、偏好和观察独立追加；所有派生状态可由原始证据和审计重建。
