## 三、第十步：教师辅助备课工作区

### 3.1 本阶段目标

完成以下业务链：

**教学问题 → 检索案例 → 选择参考经验 → 生成或改写备课内容 → 教师编辑 → 版本保存 → 学生预览 → 教案导出 → 教师主动发布。**

重点提升教师实际备课效率。

现有案例搜索、材料引用、Agent、课程编辑和学生预览必须复用。

不要新建第二套教案数据结构或第二套 Agent 系统。

### 3.2 案例检索与教案关联

教师在备课工作区能够：

1. 按教学目标搜索案例。
2. 按学生困难搜索案例。
3. 按知识点筛选案例。
4. 查看案例的教学目标、讲解步骤、提问和调整建议。
5. 查看实际原文来源。
6. 选择一个主要参考案例。
7. 根据需要增加辅助参考案例。
8. 明确区分当前已引用案例和候选案例。
9. 将参考经验用于当前课时备课。

所有案例关联必须保存固定的案例版本 ID。

不允许只保存标题而丢失原始版本。

### 3.3 备课编辑器

重点完善现有 `Prepare.vue`。

编辑内容包含：

- 教学目标。
- 学生基础。
- 教学重点和难点。
- 导入活动。
- 概念讲解。
- 课堂活动。
- 例题。
- 随堂练习。
- 独立检查。
- 教师提问。
- 学生可能回应。
- 教师调整建议。
- 案例引用。

优先复用现有内容块。

不要同时创建两套相同的编辑器。

对尚未包含的内容，优先通过现有内容块属性扩展，只有确有必要才新增字段。

### 3.4 AI 辅助改写

在现有 Agent 基础上支持：

- 对整个课时生成备课建议。
- 针对某一个活动局部重新生成。
- 根据学生困难调整讲解方法。
- 改写某一段讲解。
- 补充教师提问和学生回应建议。
- 为已有活动提供不同讲法。

每次局部生成必须：

1. 明确目标内容块。
2. 保留其他内容块。
3. 保留当前教师手动编辑。
4. 保存生成前的内容。
5. 显示原内容与新建议的差异。
6. 由教师确认是否采用。

不能直接覆盖整份教案。

默认不执行额外的 Codex 重排。

### 3.5 教案版本管理

本阶段必须重点解决：

- 教师草稿保存。
- 修改后再次保存。
- 历史版本查看。
- 保存时间及版本标识。
- 草稿和正式发布内容分离。
- 历史版本不被修改。
- 可恢复之前的教案版本。
- Agent 生成内容能够追溯到对应任务。

优先调查现有数据库结构和版本机制。

避免新建重复的教案体系。

如果确实需要增加教案版本表，使用最小增量迁移，并提供回滚方案。

特别测试并发保存：

教师在两个页面同时打开同一份教案时，旧页面不能静默覆盖新页面已经保存的内容。

### 3.6 学生预览

继续复用现有学生预览组件。

必须确保：

- 教师编辑后的内容在预览中正确显示。
- 数学公式正确。
- 天平等已有互动组件正确。
- 例题与练习顺序正确。
- 长文本、图片和引用显示正常。
- 预览不产生真实学生作答。
- 预览不会自动发布。

预览内容与保存的当前草稿必须一致。

### 3.7 教案导出

本阶段优先支持 **DOCX 可编辑教案导出**。

导出内容至少包含：

1. 课时标题。
2. 年级和学科。
3. 教学目标。
4. 学生基础和教学困难。
5. 讲解活动。
6. 教师提问。
7. 例题及练习。
8. 参考案例。
9. 原始材料来源。
10. 教案版本信息。

要求：

- 中文字体正常。
- 数学公式保持可读。
- 标题层级清楚。
- 表格和段落不混乱。
- 不泄露内部任务 ID、模型配置和运行日志。
- 可以在 Word 或 WPS 中继续编辑。
- 导出的内容和所选择的草稿版本一致。

优先复用已有依赖。

本阶段不需要同时实现复杂的 PDF 排版系统；如已有稳定 PDF 导出能力，可以复用，但不得影响主要交付。

### 3.8 教师发布

第十步不得重写第十一阶段的班级任务系统。

继续使用已有发布流程。

必须保证：

- Agent 只能生成建议。
- 教师必须主动确认使用建议。
- 教师必须主动发布任务。
- 发布前能够预览。
- 发布结果保存固定课时及案例版本。
- 旧任务继续使用原有快照。
- 发布后学生能够读取实际内容。
