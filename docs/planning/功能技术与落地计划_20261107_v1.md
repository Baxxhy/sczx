# 师承智学功能、技术与落地计划

日期 2026-11-07　版本 v1

## 一、建设目标和当前起点

师承智学面向乡村教育振兴，通过优质教学经验共享，帮助基层教师组织教学，帮助学生学习新知识、理解困难、练习应用和持续成长。

第一版形成一个可试用的网页平台，走通“教师整理经验—审核发布—教师安排学习—学生学习与练习—教师查看反馈—改进教学内容”。错题帮作为错题整理与补救模块接入。

本计划依据当前sczx源码、接口清单、页面清单和已有检查记录编制。已有36个页面、83条接口及102种调用方法，已有记录显示99项后端、694项算法、25项前端和72项浏览器检查通过。现有检查主要覆盖已迁移功能，新建模块需要新增相应验收。

目前已经启动过独立网页、业务服务、算法服务及MySQL。已有250张知识卡、65条知识关系的初始化记录，教学经验内容与完整课程仍需要编制。原版迁移留下短列表显示取舍与少量像素差异，纳入界面整合时处理。

本轮只制定建设计划。下表“已有”表示当前源码和既有验收记录支持的基础，“改造”表示需按新的平台用途扩展，“新建”表示当前未形成对应完整流程。

### 请求和数据怎样流动

学生或教师操作Vue网页，网页请求Python业务服务。业务服务校验身份、读取或保存MySQL记录，需要AI时调用Python算法服务。算法服务使用模型、检索和数学工具，返回经过结构检查的结果。业务服务再次核对任务状态和归属，保存结果，网页展示。

上传原图和教学附件保留原始文件，通过访问权限和签名链接读取。算法服务处理计算，业务数据库由业务服务管理。

## 四、先确定的数据关系

|数据对象|必须说明的内容|与已有能力的关系|
|---|---|---|
|学校、班级、任教关系|谁可以安排任务、查看哪些学生|扩展账号与权限|
|课程、单元、课时、学习目标|学什么、按怎样的关系组织、完成条件是什么|连接现有知识点|
|教学经验及版本|来源、适用情况、步骤、回应分支、审核状态|扩展知识与材料检索|
|学习活动|讲解、探索、提问、练习等具体活动与顺序|调用已有讲解、作答、图示能力|
|教师任务与学生进度|谁布置、谁参加、当前在哪里、如何恢复|复用任务状态和执行模式|
|学习事件|学生解释、作答、获得的帮助、核验结果|扩展现有学习证据|
|反馈和发布记录|哪一版内容被谁使用，问题怎样处理|支撑审阅、追踪和回退|

先写清楚字段、关系、权限和状态转换，再确定数据库表及接口。每条学习记录关联当时使用的内容版本，教师更新材料后仍可回看之前的学习经过。

## 五、从现在到落地的顺序

下列工期是按一名主要开发者、每周约20至30小时投入估算的工作量。团队人数、投入和赛事日期尚未确定，实际排期按完成条件调整。教学内容与合作协调可与软件开发交叉推进。

|阶段|先做什么与具体交付|依赖|预计工作量|完成条件|
|---|---|---|---|---|
|1 定首版|确认一个单元、师生角色、主要使用流程，画学生首页、课程页、学习页和教师页草图|本计划|2至3个工作日|能说明教师怎样发布一次学习，学生怎样从新知识开始，教师怎样看到反馈|
|2 做内容样板|编制一课的目标、引入、教法、活动、练习与检查，再扩展单元内容|阶段1|3至5个工作日，内容修订持续进行|一位审阅者能沿材料完成数学与教法检查，来源清楚|
|3 定数据与权限|设计课程、经验版本、班级、任教和任务关系，写接口约定与数据库迁移|阶段1，参考阶段2|3至5个工作日|学生、教师、管理者访问范围清楚，旧数据可继续读取，迁移可验证|
|4 接通完整一课|实现教师发布课时、学生进入新课、完成活动与练习、保存进度、教师查看结果|阶段2、3|7至10个工作日|两种身份在真实网页与数据库上走通一课，刷新后能恢复|
|5 接入教学经验与AI|实现经验编制审核、检索与引用，支持按学生回应换讲法、补基础和检查|阶段4|5至8个工作日|不同学生回应产生合理的不同指导，能追查所用内容，数学与任务状态检查通过|
|6 扩展完整单元|接入全部课时、练习、错题补救、复习与成长，完善教师任务和反馈|阶段5|5至8个工作日|新课、疑问、错题三种入口均能走通并连接后续学习|
|7 准备真实试用|部署、备份恢复、弱网体验、权限检查、成本记录、问题反馈入口|阶段6|3至5个工作日|可访问网站、可恢复数据，教师可实际使用，明确支持范围和服务安排|
|8 小范围使用|开展教师和学生试用，记录问题并修复，跟踪再次学习情况|阶段7及合作落实|建议预留2至3周观察|有实际使用记录、问题修复记录、内容反馈及连续学习记录|
|9 整理比赛材料|形成计划书、演示视频、技术说明、成本和试用成果|阶段4起持续积累，阶段8汇总|3至5个工作日|项目表述、现场演示、实现情况和已有证据相互对应|

阶段1至7约28至44个工作日。按每天4至6小时，约112至264小时，对应每周20至30小时约4至14周；实际取决于内容返工、实现复杂度和协作情况。试用观察与合作落实另计。若赛事临近，优先交付完整一课及教师反馈流程，再依据实际时间扩展单元。

### 与开发同时推进的工作

从阶段1开始联系愿意交流的教师，了解真实备课、课后指导、设备和网络条件。初期可以先做访谈与内容审阅，实际试用需要落实参与者和使用安排。

从阶段2开始记录内容制作与审阅时间，阶段4开始记录AI调用和服务器费用。以实测结果估算服务一个班级的成本。

从阶段4开始保存演示录像与版本记录。比赛材料中的用户人数、效果、合作和费用按实际发生情况填写。

## 七、怎样判断真的落地了

|方面|记录什么|怎样检查|
|---|---|---|
|功能|教师发布、学生学习、作答、恢复和反馈全过程|真实账号、浏览器和数据库联调|
|权限|教师任教范围、学生本人数据、内容发布权限|覆盖允许与拒绝访问的用例|
|教学内容|来源、数学正确性、教法适用条件和版本|内容检查与教学审阅|
|AI帮助|能否理解困难、是否引用合适材料、提示量和换讲法|固定案例回放、人工抽查与试用反馈|
|学习表现|自己的解释、独立新题与隔次复习表现|记录获得的帮助，保留原始作答；小规模试用先报告观察结果|
|教师价值|备课和调整材料所用时间、实际采用与修订情况|记录工作过程与教师反馈|
|运行|失败率、响应时间、单位学习费用和弱网恢复|实际服务日志与受控网络检查|
|持续服务|内容维护、问题响应和班级使用成本|按真实人时和账单核算|

## 八、下一项要执行的任务

先完成“首版范围与师生使用流程”，同时做第一课内容样板。确认样板能支撑学习之后，再依次确定页面、数据与接口，进入完整一课开发。后续所有任务沿本计划中的功能编号追踪，新增范围另记版本。
