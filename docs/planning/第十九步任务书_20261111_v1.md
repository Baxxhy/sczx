# 四、阶段B：离线课时下载

## B1. 离线材料包

学生可以选择一个已经授权访问的课时，点击“下载供离线学习”。

下载内容仅包含：

- 课时ID。
- 已发布版本ID。
- 学生可见标题。
- 教学目标。
- 讲解正文。
- 例题。
- 学习活动。
- 可公开的练习题干。
- 必要图片和静态资源。
- 知识点关联。
- 下载时间及内容摘要。

禁止包含：

- 教师内部备注。
- 未公开参考答案。
- 隐藏评分规则。
- 其他学生信息。
- 管理员数据。
- 模型凭据。
- 会话Cookie或Token。

由后端生成学生权限范围内的离线数据。

不能直接把完整 `/api/platform` 响应保存到本地。

## B2. 离线存储

建议采用：

- Service Worker：缓存前端应用外壳和必要静态资源。
- IndexedDB：保存明确下载的课时数据及本地草稿。
- 结构化版本记录：标识内容版本、用户范围和同步状态。

不引入新的独立同步服务。

如果采用额外前端依赖，必须说明必要性及维护成本。

## B3. 离线包管理

支持：

1. 下载指定课时。
2. 显示下载进度。
3. 显示已下载版本。
4. 查看占用空间。
5. 删除指定离线包。
6. 删除全部离线内容。
7. 识别存储容量不足。
8. 处理下载中断。
9. 下载失败后重试。

不允许因下载失败破坏之前已经成功下载的内容。

所有已下载版本必须可追溯。

# 五、阶段C：离线身份与数据安全

这是本轮P0级重点。

必须防止共享电脑上不同账号的数据混淆。

## C1. 用户隔离

本地数据必须按用户和课时版本明确隔离。

教师A、学生A、学生B使用同一个浏览器时：

- 学生A不能看到学生B的离线作答。
- 退出登录不能让后一位用户直接读取前一位用户的私人内容。
- 切换账号不能复用旧用户待同步任务。
- 不同任务的作答不能混淆。

不要在localStorage明文保存会话Token或完整学生隐私资料。

## C2. 离线重新打开

当前路由需要在线会话初始化。

必须修复以下问题：

学生下载课时 → 关闭浏览器 → 断网 → 重新打开应用 → 安全进入已下载内容。

必须明确离线身份确认方式。

如果采用本地解锁，需要保护本地草稿与个人内容，不允许通过简单修改userId绕过隔离。

不为实现此功能而存储可复用的服务器明文密码或Cookie。

## C3. 退出与清理

正常在线退出时，必须清理当前用户本地敏感内容或按照明确的用户设置执行清除。

离线退出时也要立即撤销本机访问，并在恢复网络后处理服务器会话退出状态。

浏览器缓存或离线数据不能绕过服务器后续的访问撤销。

若无法在线确认账号授权，仅允许访问符合离线授权和本地安全策略的内容。

# 六、阶段D：离线作答与可靠同步

## D1. 离线作答草稿

允许学生离线填写：

- 当前题目答案。
- 解题过程。
- 当前课时位置。
- 普通练习草稿。
- 必要的操作记录。

每条草稿必须记录：

- 本地唯一操作ID。
- 用户ID。
- 任务ID。
- 题目ID。
- 已发布内容版本。
- 服务器原始修订号。
- 本地修改时间。
- 内容。
- 同步状态。

离线输入必须先在IndexedDB保存成功，才能显示“已保存到本机”。

不能在没有持久化成功时显示保存成功。

## D2. 同步状态

至少包含：

- 已保存到本机。
- 等待同步。
- 正在同步。
- 已同步。
- 发生冲突。
- 同步失败。
- 已失效，不能提交。

这些状态必须有实际业务含义。

不需要为每个状态使用彩色徽章。

## D3. 不能使用整份旧平台数据覆盖服务器

重点检查：

`store.save()`

以及：

`PUT /api/platform`

当前聚合保存会处理多个学习记录和草稿。

离线同步不能直接把旧的整份平台状态重新上传覆盖当前数据库。

推荐增加受限的离线草稿同步接口，或者通过既有精确记录接口实现。

同步时只处理明确允许的字段。

必须具备：

1. 用户权限校验。
2. 当前任务可写校验。
3. 课时版本校验。
4. 原始修订号校验。
5. 唯一操作ID。
6. 幂等提交。
7. 冲突反馈。
8. 服务端时间校验。

## D4. 冲突处理

必须覆盖：

- 离线修改后，服务器草稿也发生修改。
- 离线时任务被教师撤回。
- 离线时学生被移出班级。
- 离线时任务已经提交。
- 离线时任务截止时间已过。
- 离线内容版本与当前版本不同。
- 同一题目在两个浏览器分别修改。

出现冲突时：

- 不能静默覆盖服务器记录。
- 不能直接丢弃离线草稿。
- 显示服务器内容与本地内容的差异。
- 允许保存本地副本。
- 对允许继续编辑的任务，经用户确认后重新提交。
- 对只读或已失效的任务，禁止绕过权限。

## D5. 联网恢复

学生恢复网络后：

1. 检查当前在线身份。
2. 读取待同步操作。
3. 对操作进行权限与版本预检。
4. 按既定顺序同步。
5. 服务端幂等去重。
6. 成功后更新本地状态。
7. 失败保留原草稿。
8. 冲突时停止相关记录的自动覆盖。
9. 显示同步摘要。

网络断开后重复恢复，不得生成重复正式作答。

服务器返回成功前不能标记“已同步”。

## D6. 独立作答与帮助状态

离线草稿重新同步后：

- 原始作答必须保留。
- 曾经使用帮助的记录不得清空。
- 未获得程序核验的答案不能自动标记正确。
- 单纯离线保存不能算任务正式提交。
- 正式作答仍经过原有服务器端核验。
- 学习记忆必须使用实际已确认的学习证据。

# 九、必须完成的端到端测试

## 流程一：离线阅读与恢复

学生在线登录 → 下载课时 → 断网 → 关闭并重新打开页面 → 安全访问已下载内容 → 阅读课时 → 返回目录 → 查看当前离线状态。

检查已下载资料完整、图片正常、权限有效。

## 流程二：离线作答与联网同步

学生在线下载任务 → 离线填写答案和解释 → 保存本地草稿 → 刷新 → 恢复草稿 → 恢复网络 → 核对身份和版本 → 同步 → 服务端重新读取 → 学生按正常流程正式提交。

验证原答案与解释一致。

## 流程三：冲突与失效

学生离线编辑 → 教师在服务器端改变任务状态或学生权限 → 学生联网 → 服务端拒绝不允许的写入 → 页面显示冲突 → 原本地草稿仍可查看或安全导出。

不得默默丢弃答案。

## 流程四：多账号数据隔离

学生A下载材料及保存草稿 → 退出 → 学生B登录同一浏览器 → 无法读取学生A私人记录 → 学生A恢复正确身份后按安全机制读取允许保留的内容。

不得简单通过前端切换studentId获取其他学生数据。

## 流程五：全平台视觉回归

分别使用教师、学生和管理员账号打开主要页面。

检查长内容、空数据、错误状态及主要业务按钮。

重点保证：

- 教师备课可继续保存。
- 课程与题目正常使用。
- 考试正式提交正常。
- 实时课堂正常。
- 分层练习正常。
- 教研交流正常。
- DOCX导出规范保持不变。
