# 优质教师经验结构与可信来源设计

日期：2026-11-14。复用 CaseDraftContent.data / CaseVersion.data，不新增数据表或迁移。

## 字段与用途

|语义|现有或增强字段|用途|
|---|---|---|
|学科、年级|subject、grade|匹配硬条件；未知值不默认为七年级数学|
|知识目标|knowledgeIds、knowledgeLinks、experience.knowledgePoints|数据库知识点关联与可读名称|
|目标、学情|experience.goal/studentBase/difficulty|说明希望学会什么、遇到什么问题|
|诊断依据|experience.diagnosis（新增）|需观察的作答、提问或活动；不作未经证实的认知标签|
|具体教法|experience.strategy（新增）、introduction、steps|把方法落实为能执行的教学动作|
|追问与调整|questions、responses、adjustment|预期回应是设计假设，不能伪称已发生课堂效果|
|边界|boundary|记录不宜使用情境；本轮遇到非空边界会退化，等待教师核对|
|效果检查|effectCheck（新增）|说明如何换题独立检查；不是已证实有效的结论|
|来源|references、provenance（新增）|保留材料ID、片段ID、逐字引文、作者、链接及许可声明|
|审核|draft.reviewed、experienceReview（新增）|服务端审核者、时间及当时来源声明|
|版本|CaseVersion.id/number/data/published_at|不可变发布版本；当前案例撤回不删除历史依据|

结构化提取的三个新增字段与其他原文字段相同：非空须有对应field及逐字原文引用，不能支持的内容留空，额外建议只能放suggestions。`ai_schemas.Evidence`与`model_jobs.execute`共同校验。人工编辑后的适切性由审核者负责，系统核对引文是否存在，不推断全文真实。

## 来源状态

|kind|含义|默认可否当已审核经验匹配|
|---|---|---|
|unknown|历史或来源未核验|否|
|teacher|教师提供并确认；须写作者及确认依据|审核、许可、适用字段满足后才可作为候选|
|public|公开材料整理|同上；公开可见不等于取得再分发许可|
|team|团队自编|同上；显示为自编，不能改称名师|
|ai_candidate|AI辅助候选|否；管理员须核对、修订并明确最终来源才能重新审核|

provenance还包含author、evidence、authorization、authorizationEvidence。许可状态为unknown、internal、redistribution_confirmed；声称许可已确认时必须有依据。来源类别是管理员对材料的声明，系统没有自动核实教师身份或法律许可真实性。

## 生命周期与兼容

1. 上传原件、解析并修订识别文本；原文与修订历史保留。
2. 提取进入AI候选草稿；手工新建为未核验，不自动继承名师称谓。
3. 在现有管理案例编辑器填写教法、诊断、效果检查、来源及许可，关联原文。
4. 保存正文或来源变更撤销审核并丢弃旧审核凭据；客户端不能伪造审核者。
5. 管理员人工核对后，由服务端写审核记录。无变化保存保留原审核，避免发布前重复保存误撤销。
6. 发布新CaseVersion。再次编辑须创建新草稿、重新审核及发布；旧版本和已发布任务不重写。
7. 撤回停止新检索，已保存的引用仍可定位。教研使用反馈继续沿用原接口，本轮不建新反馈库。

只读时旧数据缺字段或来源格式无法识别，显示未核验，不批量回写原库；不迁移既有发布记录的来源类别。更改来源类别不能等同于真实性审定。

## 工程位置与验证

`experience_policy.py`负责来源解析、写入校验与匹配；`library.py`负责兼容读取；`library_routes.py`负责服务端审核与版本发布；`MaterialWorkbench.vue`、`CaseArticle.vue`展示字段与来源。

`test_experience_policy.py`验证未知/错误格式、无依据教师声明、无许可依据、AI候选和审核来源变更的退化；`test_experience_mysql.py`验证真实API权限、审核保存、新版本及历史保护。正式库未升级，运行中的8099未重启。
