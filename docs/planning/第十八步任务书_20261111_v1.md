1. 打开学生学习页。
2. 点击语音输入。
3. 实际说出“x加3等于5”。
4. 查看是否获得识别文字。
5. 人工修改识别内容。
6. 确认后填入问题。
7. 验证确认前没有提交。
8. 切换题目并确认旧语音任务取消。
9. 打开一段中文教学讲解。
10. 实际点击朗读。
11. 验证暂停、继续和停止。
12. 验证切换内容时旧朗读停止。

记录：

- 操作系统版本。
- 浏览器版本。
- 实际麦克风。
- 是否获得识别文本。
- 中文语音列表。

# 四、阶段C：第十八步实时课堂、分层教学和教研交流

实施前阅读总体20步计划第十八步及现有班级、课程、考试、学情、学习记忆与案例管理代码。

不要重新建设第二套班级、任务和教师账号系统。

## C1. 实时课堂

教师应能：

1. 从已发布课时创建课堂。
2. 选择当前班级。
3. 开始课堂。
4. 推送一道题目或互动活动。
5. 查看学生加入状态。
6. 查看实时作答进度。
7. 查看已提交人数。
8. 查看正确、错误及未核验情况。
9. 根据实际回答决定是否继续讲解。
10. 结束课堂并保留记录。

学生应能：

1. 进入所属班级的当前课堂。
2. 收到教师推送的活动。
3. 查看题目。
4. 提交实际答案。
5. 修改尚未提交的草稿。
6. 查看教师公开的反馈。
7. 结束课堂后保留自己的学习记录。

实时功能优先使用现有HTTP/SSE基础能力。

如果轮询能够满足明确的刷新要求，可先使用有界轮询。

不得为了实时课堂强行引入新微服务或复杂消息队列。

## C2. 实时状态与数据可靠性

重点验证：

- 教师只能操作本人班级课堂。
- 学生只能进入授权课堂。
- 一名学生重复提交不会重复计数。
- 网络断开后可以恢复。
- 切换课堂不会串用题目。
- 旧请求不能覆盖新课堂状态。
- 教师结束课堂后不能继续新增正式回答。
- 课堂结束后保留学生原始作答。
- 课堂实时统计与数据库一致。

不允许使用前端固定数字伪装实时参与人数。

## C3. 分层教学

复用第十四、十五步已有学习证据和学情分析。

教师能够：

1. 查看当前知识点的有效作答依据。
2. 选择需要补基础的学生。
3. 选择需要巩固的学生。
4. 选择可以进行拓展练习的学生。
5. 调整学生分组。
6. 为不同分组发布不同练习。
7. 查看各组实际完成情况。
8. 查看干预后新增独立作答。

分组应当是可调整的教学安排。

不能将学生固定标记为“差生”或“低能力学生”。

系统推荐分组必须保留依据，并由教师确认。

分层练习优先复用现有题库、试卷及补充任务能力。

## C4. 教研交流

围绕现有教学案例和教师教案，实现：

- 分享。
- 收藏。
- 讨论。
- 引用。
- 改编。
- 使用反馈。

需要保证：

1. 原始案例版本不可变。
2. 改编生成新的独立草稿。
3. 保留原作者和来源。
4. 未发布案例不能被其他教师直接访问。
5. 教师私人教案不能被自动公开。
6. 评论和反馈有明确作者与时间。
7. 用户可以撤回自己有权限撤回的内容。
8. 改编内容必须经过正常审核才可正式发布。

不能把AI生成的使用效果描述成真实课堂实践反馈。

## C5. 学习成长记录

复用现有LearningMemory、Attempt、RepairAttempt和考试记录。

展示：

- 已学习课时。
- 实际作答记录。
- 有效复测证据。
- 错题补救历史。
- 近期复习活动。
- 当前知识点的证据状态。

避免新增一套重复的学习画像。

不得生成没有证据支持的精确掌握度百分比。

# 六、必须执行的三条真实业务流程

### 流程一：实时课堂

教师开始课堂 → 多名学生加入 → 教师推送数学问题 → 学生实时作答 → 教师查看提交情况 → 教师追加讲解 → 结束课堂 → 学生重新登录查看历史。

### 流程二：分层教学

教师查看知识点证据 → 生成候选分组 → 人工调整 → 发布不同练习 → 学生分别完成 → 产生新学习证据 → 教师查看变化。

### 流程三：教研交流

教师A分享已审核案例 → 教师B阅读和收藏 → 教师B讨论 → 创建改编教案 → 保留原始来源 → 审核发布改编版本 → 教师A查看反馈。

以上流程必须使用真实数据库和多角色账号。

不得用静态页面代替。
