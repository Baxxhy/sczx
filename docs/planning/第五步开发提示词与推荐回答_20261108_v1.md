### 2. 按职责使用技能

必须实际读取适用的 SKILL.md，将规则用在对应工作中。

- **grill-me / grilling，必须使用。** 优先读取 `/root/.agents/skills/grill-me/SKILL.md` 和 `/root/.agents/skills/grilling/SKILL.md`。入口技能委托给 grilling；按当前工具能力执行其实际规则。按决策依赖分轮提问，每轮问齐当前前提已经明确的问题，每题给推荐答案和理由，让“是”能够接受推荐，然后等待回答。事实调查按该技能要求交给独立上下文的只读子代理，限定范围，不能向用户索要可自行查到的工程事实。
- **writing-plans。** 将确认后的范围写成按依赖执行的任务，明确模块边界、必要迁移、接口、页面和可观察的验收结果。
- **executing-plans。** 跟踪实现、真实调用、故障修复和剩余验证；持续推进到确认范围的交付。
- **information-architect。** 让学生识别、确认、求助及管理员查看任务的入口与已有业务对象对应，避免出现孤立的模型演示台。
- **frontend-design / design-taste-frontend。** 处理生成内容、确认编辑、任务状态和结果阅读的布局，继承现有 Nova 视觉，不重新随机选择主题。
- **ui-ux-pro-max。** 检查长等待、处理中、错误与重试、音频控件、键盘焦点、可访问名称和响应式。优先使用与当前交互有关的规则，不引入另一套组件或动画库。
- **systematic-debugging。** 在跨 API、任务、数据库、SSE 或页面状态的故障出现时，以复现和证据定位根因。
- **verification-before-completion。** 核对每项完成声明的代码、真实调用、数据库与浏览器证据；区分适配已实现、真实调用已验证和业务流程已验证。

已有确认直接沿用：Vue + JavaScript、Python 业务服务、MySQL、独立账号、任务快照、原图保留、全模型外部 API、CPU 部署、简单可运行、精致且清晰的网页界面、不建设费用统计和预算功能。按技能只澄清仍影响结果的决策。推荐回答不是用户已经作出的选择；用户明确授权按推荐执行后沿用授权，不重复询问。

### 3. 确定第五步的完整范围

完成六类外部模型能力的统一配置、调用适配、结果解析和错误处理：文本、图文/OCR、Embedding、Rerank、ASR、TTS。整体计划明确要求图片识别、结构化讲解与检索向量生成通过实际请求完成。本提示词推荐六类能力均做一次最小真实调用；实施前通过 grilling 确认 Rerank、ASR、TTS 本步的实调用范围，按实际确认调整下文验收，不把建议当成现有授权。

每类能力可以使用不同供应商和模型，依据实际服务文档映射协议，不假设它们共享同一模型或同一个 HTTP 端点。

以下实现与验收条款按推荐范围展开。访谈收到不同选择时，同步更新计划、入口与验收范围；六类外部适配、图文/讲解/向量真实请求等整体计划已有要求继续保留。

首个学生业务流程推荐落在现有课程学习与题图求助：原图上传 → OCR → 学生核对 → 根据当前课时和实际问题生成指导 → 结构校验与适用数学检查 → 保存 → 教师回看。纯文字求助使用同一套任务和结果保存能力。

Embedding 和 Rerank 在本步完成可复用接口和实际数据调用；ASR 和 TTS 完成上传音频转文字、文字生成可播放音频的最小入口。完整资料处理属于第六步，课程内容建设属于第七步，混合检索属于第八步，LangGraph 教学编排属于第九步，学生完整语音交互属于第十七步。本步的能力验证不能被后续模块未完成阻塞，也不能将后续模块整体提前纳入。

采用单个模块化 FastAPI 业务服务和 MySQL 保存任务。先检查 HTTP 客户端等已有能力，确需依赖时选一种成熟实现。当前规模优先采用单服务内可运行的工作循环与明确生命周期，不为任务执行额外引入 Redis、Celery、消息集群或多服务平台。模型全部外部调用；保留 CPU 上的数学、文档和音频格式处理能力。

### 4. 建立按能力选择的 API 适配层

借鉴 ApiPoolProvider 的可复用部分，统一选择配置、发送请求、解析响应、超时和错误映射。先调查旧实现，不能将“已有 API 池”视为六类能力已经接通。

为每个配置明确能力类型、供应商、模型标识、服务地址配置来源、凭据环境变量名、必要的格式和超时参数。允许每类能力有多个配置，轮询和故障切换只在兼容的能力池内进行。凭据通过本地忽略配置或环境变量读取，公开示例只含占位符。保留旧配置兼容时提供明确映射和缺失字段反馈。

统一接口至少表达以下输入输出，名称可按工程调整。

|能力|输入|规范化输出和实际检查|
|---|---|---|
|文本|消息、教学上下文、可选输出结构|可读文本或经校验的结构化对象、调用状态|
|图文/OCR|已上传原图及必要问题|识别原文、数学表达、题目区域或疑点；保留原图关联|
|Embedding|一条或多条文本|与输入顺序一致的数值向量、模型与维度；检查数量、维度和有限数值|
|Rerank|查询、带稳定 ID 的候选文本|候选 ID、顺序及供应商分值；检查遗漏规则、重复与越界，不擅自统一不同服务的分值含义|
|ASR|真实音频文件、语言等必要选项|转写文字、音频关联和服务实际提供的时间信息；允许人工修订|
|TTS|文字、可用音色和输出格式|真实音频文件资源、媒体类型和可播放地址；不以浏览器朗读代替外部 TTS|

明确未配置、不支持该能力、认证失败、服务限流、超时、网络失败、无效响应和结构错误。后台保留可追踪的请求关联 ID、能力、模型、尝试次数及耗时等运行信息；不建设费用、财务配额或预算界面。

### 5. 结构化结果和数学核对

为 OCR、分步指导及数学核对定义 Pydantic 输入输出模型与版本。建议指导结果包含当前问题、学习目标、引导步骤、所需补充信息和数学核对结论；具体字段围绕现有页面设计，避免提前设计庞大的教学本体。

实际执行模型结果解析与 Pydantic 校验。供应商支持严格结构化输出时使用其实际能力；不支持时显式解析并校验，结构错误允许有限修正重试，失败进入可重试任务状态，不用默认对象伪装成功。记录原始识别、人工修订与最终使用内容的关系。

使用 SymPy 核对当前首课涉及的数值、代入、等价变形及一元一次方程，明确变量域、非零等必要条件。将“已核对”“未能核对”“发现不一致”分开保存和显示。模型自称正确、结构校验通过以及程序得到未知结果，都不能等同于数学正确。自然语言解释质量与符号计算分别处理。

本步触及的智能结果由后端生成和保存。移除相应流程中固定答案 `7`、前端字符串相等或预设提示冒充通用智能判断的路径。固定练习可以继续作为明确的课程题目，服务端需读取其真实题目和参考答案。范围外的问题允许保存并进入待核对状态，不错误判成已掌握。

前端只渲染已支持的文本、公式和固定组件；模型提供可视化配置时使用经校验的 VisualizationSpec，不执行模型生成的 JavaScript。

### 6. 后台任务、持久化与重试

通过迁移增加必要的后台任务、执行尝试和事件记录。任务至少关联创建账号、能力、业务类型、相关课时/任务/学生记录/题目或文件、输入快照、状态、当前步骤、结构化结果、错误以及开始和结束时间。学习任务 ID 与后台运行任务 ID 使用清楚的不同字段。

采用 `queued → running → succeeded / failed` 等足够表达本步行为的状态。重试保持同一业务关联，保存新的执行尝试与原因；保留上一次结果。对正在执行的相同提交做简单去重，防止双击生成两份业务记录。后台完成结果只写入对应记录，不能因当前页面已经切换学生或任务而写错对象。

先记录任务再执行外部请求，避免浏览器断开导致任务丢失。数据库会话和事务不跨越漫长模型等待。进程停止后，已有成功结果可读取，遗留执行有明确的恢复或可重试状态；不宣称外部调用具备无法保证的精确一次执行。是否自动恢复由 grill-me 确认，默认推荐中断后标明可重试。

自动重试只针对可恢复错误，次数有上限；认证、能力缺失等错误给出明确配置状态。超过上限后提供手动重试，不无限轮询。新任务与结果使用清楚的业务接口，处理现有聚合自动保存可能覆盖新结果的问题，不能继续把整个任务对象交给浏览器反复覆盖。

### 7. SSE 和页面恢复

提供任务创建、列表/详情、结果、事件订阅和手动重试等必要接口。具体路由自行根据现有工程命名，不为了通用化增加无消费者的接口。

SSE 事件表达真实步骤，例如排队、读取题图、识别、生成指导、数学核对、保存、成功和失败；有事件 ID、运行尝试与时间。只显示实际已知的进度，不用计时器生成虚假百分比。需要人工确认的 OCR 结果作为一次任务的终态结果，页面进入待核对状态，确认后再创建指导任务，避免后台 worker 一直等待人工输入。

页面刷新、离开后重返以及 SSE 断线时，先读取服务端任务快照，再恢复事件；支持事件游标或等效的缺失状态恢复。终态关闭订阅，切换页面清理客户端连接，后台任务按确认规则继续。必要时用任务详情轮询作为断线恢复方式，并保持同一业务结果。

沿用现有同源 Cookie 会话和 Vite `/api` 代理。开发代理、API 和实际部署链路都要检查流式事件是否及时到达，不能只验证普通 JSON 请求。

### 8. 接入学生端和教师回看

在已有学习帮助面板与题图入口接入流程。题图先获得后端文件 ID，调用 OCR 后展示原图和可编辑识别结果；学生确认后再生成针对当前问题的指导。识别为空、不确定符号或缺少作答时，允许补充和重新识别，原图与前次结果继续可查。

指导必须读取当前发布快照、当前题目、学生问题与必要的作答记录。首版不使用全库 RAG 时明确实际上下文来源，不能编造引用、教师背书或检索结果。推荐先给提示和关键问题，再按学生操作展开解释；独立检查请求帮助后正确标记当次尝试，换题重新记录独立性。

将请求、OCR 结果及修订、帮助内容、原图、数学核对状态与后台任务关联保存。教师从现有学情页能查看该学生的真实帮助过程和原作答。生成结果不能自动覆盖教师已经保存的反馈，也不能改变已发布任务快照。

### 9. 验证向量、重排和语音能力

用已有首课文本或明确标记的短材料实际请求 Embedding，再用当前问题和一组候选材料请求 Rerank。结果保存到本步需要的任务记录中，验证真实向量和候选排序可重新读取。第八步再建设完整索引、混合检索和发布更新。

在管理端已有“反馈与运行”中放置紧凑的能力验证入口：上传真实短音频，查看与修订 ASR 文字；输入短文本，调用外部 TTS，播放并重新读取保存的音频。可以复用支持相应媒体类型的文件接口，扩展时确保原有题图行为继续可用。学生完整录音、连续语音对话和朗读体验后续推进。

每类能力标明未配置、可调用、最近验证成功或最近失败的实际状态，配置存在不代表调用成功。如果真实服务或配置缺失，完成独立可做的适配和页面，但保留该项未验收，并只请求确实缺失的配置；不能自行缩减已确认的真实调用范围或用固定结果通过验收。

### 10. 页面视觉与交互

前端保持 Vue 3 + JavaScript、Vite、Vue Router、Pinia、shadcn-vue、Reka UI、Tailwind、Lucide、motion-v、Reka Splitter 和 VueDraggable。组件源码保留在项目内，不引入 React、TypeScript 或重复同类组件库。

保持当前深色正文、清楚的按钮、Nova 中性色与课程视觉。桌面主内容与操作区域有合理比例，长回复使用阅读宽度、分段和局部滚动，避免少量内容撑起巨大的空白卡片；平板和手机按阅读顺序排列。任务详情按需展开，不把日志字段堆在学生页。

优先用布局、间距、标题和明确操作解释流程，保留必要教学内容。删除重复标签、口号、装饰说明与每区块的帮助段落。补充信息用 info + tooltip，表单仍需可见标签和可访问名称。

生成中保留原输入和已读内容，提供可感知的忙碌状态；错误在对应操作附近显示并能被读屏读取，重试后焦点合理恢复。检查弹窗、公式、原图、音频播放、键盘操作、减少动画偏好及移动端溢出。

### 11. 按依赖实施和验证

确认访谈后先写第五步实施计划，建议顺序为：现状与契约 → 统一配置与六类适配 → Pydantic/数学核对 → 任务迁移与工作循环 → SSE/恢复 → 学生 OCR 与指导 → 教师回看与管理能力验证 → 故障、重启和视觉验收。按实际依赖调整，不提前开始完整 RAG 或 Agent 编排。

验证必须覆盖以下结果。

|场景|完成证据|

## grilling 访谈依赖与推荐回答

以下是执行提示词时的决策准备，不要求照表逐条机械询问。执行者调查的事实、已有用户确认和用户新的回答都会改变下一轮。

|轮次前提|需要决定的问题|推荐回答与理由|
|---|---|---|
|第一轮：已核对现有页面|首个完整业务闭环落在哪里？|采用学生学习页的文字/题图求助，配套教师回看。现有入口和记录关系可直接验证模型服务的教学价值。|
|第一轮：已查清真实服务能力|各能力是否允许分别选供应商与模型？|允许；文本/图文优先兼容现有可用配置，其他能力按服务真实协议分别映射。旧同池单模型限制不适合六类能力。|
|第一轮：已核对整体计划与服务配置|Rerank、ASR、TTS 本步也做最小真实调用吗？|推荐做；六类能力各用短输入实际调用一次，不扩展完整检索或学生语音产品。若用户选择分期，记录精确交付范围和未验证能力。|
|第一轮：已确定持久任务基础|离开页面与服务重启怎样处理？|页面离开后台继续；进程重启后保留结果，中断执行标为可手动重试。先用清楚的状态保证可恢复使用。|
|第二轮：学生图文流程已选定|识别后什么时候进入指导？|先显示原图和识别内容，学生修订确认后再生成。避免错误符号直接进入后续数学推导。|
|第二轮：指导入口与使用场景已明确|指导直接给答案还是逐步展开？|优先提示、关键问题与分步展开；记录每次帮助，独立检查帮助后换新题。符合当前教学流程目标。|
|第二轮：数学能力范围调查完成|数学结果不确定时如何呈现？|保留内容与原作答，标为需核对；有程序证据才标为已核对。教师可回看，不据此直接判定掌握。|
|第二轮：真实配置和调用条件已明确|ASR/TTS 在本步从哪里使用？|先在管理端提供上传、转写、修订、合成和播放的小入口，完成实际调用；完整学生语音体验按第十七步推进。|
|第三轮：故障类型已核实|自动重试和重复点击怎样处理？|可恢复错误有限重试，认证/未配置直接反馈；超限手动重试并保留尝试记录；同一运行中的重复提交复用已有任务。|
|第三轮：实调用范围已确认、能力逐项盘点完成|确认要真实验收的能力缺少服务时如何处理？|已具备条件的能力继续实现与验证；缺项明确列为未验收，补齐对应配置后完成真实调用，未达到确认范围时不能宣布第五步全部完成。|

每轮每题需要给出简短推荐理由，等待用户回答后再重算依赖。最后复述实际确认的范围、入口、结果保存、人工确认、重试与验收标准，待用户确认共同理解后实施。

提问格式沿用 grilling：`❓ Q1 — 问题标题：具体问题`，下一段使用 `➡️ 推荐：答案与简短理由`。同一轮不放入依赖本轮其他未回答问题的下游决策。本文按依赖整理了问题，执行者仍须根据用户实际回答重算每轮，而不能把推荐表直接作为确认记录。

若用户希望沿用上面的推荐，可以在开发启动时回复：

> 第五步按本文推荐方案执行：六类外部 API、统一配置与适配、MySQL 持久后台任务、SSE 真实进度、学生文字/题图求助与教师回看、管理端最小语音和向量能力验证。沿用已确认技术与视觉要求。常规实现细节自行判断，发现尚未覆盖且影响结果的产品决策再按 grilling 分轮询问，推进到真实调用和浏览器验收完成。
