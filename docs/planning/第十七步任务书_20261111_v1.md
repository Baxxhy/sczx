## 第四部分：第十七步新增功能

### A. 语音功能

复用现有 `SpeechInput.vue` 和 `SpeechReader.vue`。

需要验证：

- 语音开始、停止和异常恢复。
- 语音识别文字修订。
- 数学表达式识别确认。
- 识别确认后才提交问题。
- 长文本分段朗读。
- 暂停、继续和停止。
- 切换题目后取消旧语音任务。
- 麦克风拒绝、无声音和服务不可用时正常回退。

必须分别提供真实设备测试与自动化模拟测试的证据。

### B. 数学互动教具

复用已有天平与 VisualizationSpec。

优先新增方程变形步骤教具，支持：

- 两边同加。
- 两边同减。
- 两边同乘。
- 两边同除非零数。
- 查看变形后的方程。
- 查看运算依据。
- 撤销、重置。
- 保存学生解释。

服务端必须检验操作与数学状态。

不允许模型生成任意JavaScript并直接在页面执行。

### C. 题库

建立支持长期使用的题库。

每道题至少具有：

- 稳定ID和版本。
- 题干。
- 学科、年级和知识点。
- 题型。
- 分值。
- 参考答案及解析。
- 来源。
- 审核状态。
- 数学核验状态。

支持教师手动录题、引用已有课程题目和AI生成候选题。

AI题目默认待审核。

题目修改后必须保留历史版本，不能影响已发布课程和试卷。

### D. 智能组卷

教师能够：

1. 选择单元和知识点。
2. 设置题目数量。
3. 设置题型和难度。
4. 设置总分。
5. 从题库生成候选试卷。
6. 手动增加、删除、调整题目。
7. 修改顺序和分值。
8. 预览学生试卷。
9. 保存草稿。
10. 审核发布。

智能组卷优先使用确定性约束筛选。

不能因为题量不足而自动加入无关知识点题目。

如题库不足，应显示具体缺口，允许教师选择是否生成候选题。

### E. 考试业务闭环

建议建立最小必要的试卷、发布任务、答卷、批阅记录及版本数据结构。

必须支持：

- 班级考试发布。
- 开始和截止时间。
- 考试时长。
- 学生考试列表。
- 答题草稿保存。
- 题目切换。
- 正式提交。
- 提交后只读。
- 服务器端时间控制。
- 重复提交幂等。
- 考试版本固定。
- 教师人工批阅。
- 成绩确认与发布。
- 教师讲评。
- 考试错题转入现有错题帮。

学生端绝不能提前获取教师版答案、评分标准或未公开成绩。

### F. 数学评分

明确区分：

1. 程序已核验正确。
2. 程序已核验错误。
3. 无法可靠核验。
4. 教师人工确认。

应用题不能仅凭最终数值一致就自动给满分。

不能让模型直接决定所有题目的分数。

成绩应由各题得分准确汇总，人工调整必须保留审计记录。

### G. Word及批量导出

复用已完成的规范化 DOCX 导出。

严格执行：

- 中文宋体。
- 英文及数字 Times New Roman。
- 全文纯黑。
- A4纸张。
- 统一标题和正文样式。
- 合理分页。
- 清晰的数学表达式。

至少支持：

- 学生版试卷。
- 教师版试卷。
- 学生答卷。
- 班级成绩记录。
- 学习记录导出。

学生版不得包含参考答案和内部评分规则。

导出的数据必须满足用户权限和试卷版本约束。

## 第六部分：必须真实执行的业务流程

至少完成三条端到端流程。

**流程1：教师组卷与发布**

教师登录 → 从题库选题 → 设置分值 → 智能组卷 → 手动修改 → 审核 → 发布给班级 → 学生收到考试。

**流程2：学生考试与教师批阅**

学生开始考试 → 答题 → 保存 → 刷新恢复 → 提交 → 系统自动核验可判题 → 教师批阅剩余题目 → 发布成绩 → 学生查看讲评。

**流程3：考试错题补救**

学生考试答错 → 成绩公布 → 进入错题帮 → 查看原题 → 完成补救 → 独立复测 → 学习记忆更新 → 教师查看新增证据。

所有流程必须使用实际数据库和有效的多角色账号。

## 第七部分：安全与工程约束

必须遵守：

1. 使用隔离MySQL测试。
2. 不清理正式业务数据。
3. 不修改历史已发布课时。
4. 不覆盖学生原始答卷。
5. 不将待审核题目自动发布。
6. 不将未核验答案自动判正确。
7. 不向学生返回教师内部答案。
8. 不引入第二套账号或模型任务系统。
9. 不新增无必要的微服务。
10. 不提前建设实时课堂和离线同步。

考试应有明确的权限、版本、时间和提交边界。

本阶段按普通在线教学考试功能验收，不得宣称已经具备专业远程监考或防作弊能力。
