# 第三步使用与实现说明

日期 2026-11-07　版本 v1

## 已确认的使用规则

根据 grill-me 访谈与用户“按照推荐的来”的授权，采用一个演示班级和一名可操作学生。固定示例学生单列为教学参考。首课流程从案例阅读开始，到学生收到教师反馈结束。

教师每次发布创建独立任务，保存教案、学习目标、活动顺序和检查题快照。后续编辑保存在教案草稿中。原任务的学习记录和发布内容保留，可在班级任务列表重新进入。

## 运行与首课操作

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
npm --prefix frontend run build
```

默认端口 5177，端口占用时 Vite 输出实际可用端口。

1. 切换教师空间，打开教学案例，阅读案例后选择“用于备课”。修改学习目标、学生基础和活动，可拖拽或使用手柄上下方向键调整顺序。
2. 打开学生预览，确认后继续发布，选择演示班级与日期，确认发布。班级列表中可以进入每次发布的任务学情。
3. 切换学生空间，从学习任务进入本课。页面读取该任务的发布快照，可操作天平、保存解释、请求演示帮助并选择题图。
4. 在独立检查中填写答案与解释。提示记录绑定当前尝试，换新题后重新记录独立状态。错误作答进入对应任务的错题帮。
5. 从错题进入补救，完成固定变式并返回任务。提交本课结果。
6. 切换教师空间，在该任务学情中查看小林的解释、原作答、提示与补救，保存教师反馈。学生结果页及消息入口可读取反馈。

课时、案例与当前用户操作均为演示。预设学习指导和固定变式在当前阶段用于验证交互。自定义题图与题目可保存，固定补救示例的范围通过 info 提示呈现。其他单元课时显示待开放。

## 工程与数据

每个业务页面有独立 Vue 文件。三端共用布局、内容编辑器、任务列表、空状态与基础组件。状态管理位于 `frontend/src/store.js`，浏览器业务适配位于 `frontend/src/services/platform.js`。

业务方法集中处理读取、保存、发布、选任务、作答、帮助、错题、补救、提交与反馈。实体使用稳定 ID 和时间字段，任务关联班级、课时、发布快照及学生记录。页面后续通过这些业务入口接入 Python API 与 MySQL。

新存储键为 `shicheng-platform-v1`。首次读取时兼容 `shicheng-vue-prototype` 和 `shicheng-nova-prototype-v2`，旧记录迁入历史任务，保留旧键。旧案例会话草稿同时恢复。

教案、作答草稿、解释、帮助、原图、天平状态、补救与反馈自动保存。保存失败在页面顶部显示并提供重新保存。数据读取失败提供重新读取、导出与重置入口。重置会清除当前演示，操作前显示后果并要求确认。

管理端支持案例草稿保存、核对发布、反馈处理和演示任务重试。发布的案例标题与内容可在教师案例页读取。演示调试折叠区可分别触发下一次保存或发布失败。

## 技能使用

grill-me / grilling 用于明确发布快照、身份共享、任务关联及重置规则。writing-plans 与 executing-plans 用于安排实现。information-architect 用于页面和实体关系，frontend-design、design-taste-frontend 与 ui-ux-pro-max 用于保留现有视觉并检查实际页面。verification-before-completion 用于完成声明与实际检查结果的核对。
