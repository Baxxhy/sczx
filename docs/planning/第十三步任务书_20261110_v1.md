# 三、阶段A：第十二步指导质量定向修复

# 五、第一模块：修复当前错题判分问题

这是第十三步的第一优先级。

当前 `grading.py` 存在：

```python
REPAIR_EQUATION = "z + 2 = 9"
```

且 `assess_repair(answer)` 始终依赖这一固定题目。

这是明确的功能缺陷。

## 5.1 必须修改判分方式

新的补救结果必须关联：

- 原错题ID。
- 当前补救方案ID。
- 当前变式题ID。
- 变式题的数学表达式。
- 经过核验的参考答案。
- 学生实际答案。
- 学生解题过程。
- 是否使用提示。
- 程序核验状态。
- 作答时间。

判分必须依据实际变式题。

不能继续使用全局固定常量判分。

## 5.2 历史记录兼容

历史补救记录不得自动重算并覆盖。

必须区分：

- 历史固定补救记录。
- 新版动态补救记录。

旧记录继续可查看。

如果历史记录无法关联到明确的实际练习题，应保留原有结果和历史判分口径，并标明其来源限制。

不能把原来固定题的正确结果解释为学生已经掌握了另一道原错题。

## 5.3 判分要求

支持以下状态：

- `verified_correct`
- `verified_incorrect`
- `unverified`

只有程序可以可靠验证时，才能标记正确或错误。

无法确定答案时：

- 保留学生原始作答。
- 标记需要核对。
- 不自动判为正确。
- 允许教师进行人工确认。

不得直接使用模型自称正确的结果判定学生已掌握。

# 七、第三模块：拍照录题与OCR确认

学生：

# 八、第四模块：错因分析

错因分析是第十三步的核心功能之一。

但必须避免未经证据支持的学生能力判断。

## 8.1 初始错因类别

建议支持：

- 概念理解错误。
- 运算步骤错误。
- 符号处理错误。
- 条件遗漏。
- 题意理解错误。
- 计算错误。
- 其他或待确认。

这些类别仅作为初始分类。

允许后续扩展。

## 8.2 分析输入

依据：

- 原题。
- 学生原始答案。
- 学生解释。
- 已知参考答案（如果可信且允许使用）。
- 当前知识点。
- 同题历史作答。

## 8.3 输出

包含：

- 建议错因。
- 对应的学生原始错误证据。
- 可能涉及的知识点。
- 需要补充的前置知识。
- 建议补救策略。
- 不确定性说明。

例如：

原题：

`x - 3 = 5`

学生回答：

`x = 2`

如果学生解释表明“将右边的5减3”，可以建议检查等式两边共同运算的理解。

不能只根据 `x=2` 就直接断言学生完全不理解等式性质。

## 8.4 人工确认

学生可以修改错因。

教师有权限时可以查看并确认。

未确认的模型推测不得标记为最终事实。

# 九、第五模块：分步补救

必须根据不同错题生成不同补救内容。

## 9.1 补救流程

推荐：

1. 查看原题与原作答。
2. 理解错误可能发生的位置。
3. 提供一条针对性的提示。
4. 用相似但不同的例子讲解。
5. 让学生回答一个关键检查问题。
6. 根据回应继续讲解或转入变式题。
7. 保存过程和帮助记录。

复用第十二步多轮指导能力。

不要新建第二个通用聊天Agent。

## 9.2 补救目标

每个补救方案必须明确：

- 需要解决的具体错误。
- 对应知识点。
- 为什么采用当前补救方式。
- 预期学生能够完成的操作。
- 如何检查是否得到改善。

不得默认每道题都需要相同数量的讲解步骤。

## 9.3 数学安全

涉及公式时必须遵循：

- 已知错误不能作为正确知识讲授。
- 不能直接把模型生成答案当成正确答案。
- 数学表达式无法核验时不得自动判定掌握。
- 对条件不完整的题目，应先确认条件。
- 允许学生停止补救并返回错题列表。

# 十、 第六模块：变式练习与独立复测

## 10.1 变式题设计

变式题应当：

1. 与原错题知识点相关。
2. 改变数值、条件或题目结构。
3. 保留需要考查的关键知识。
4. 具有可验证的正确答案。
5. 避免只替换字母导致机械模仿。
6. 避免与原题完全相同。

生成完成后先进行程序验证。

不能通过验证的题目不能自动进入可评分练习。

## 10.2 复测规则

区分：

- 补救过程中接受帮助的练习。
- 补救结束后的独立新题。

只有独立新题且答案经过可靠核验时，才能形成独立复测通过记录。

原题使用帮助不能被清除。

独立复测必须重新记录实际作答。

## 10.3 补救结果

建议状态：

- 待补救。
- 补救中。
- 待独立复测。
- 独立复测通过。
- 独立复测未通过。
- 需要人工核对。

- 学生解释。

Spec必须使用严格Schema验证。

模型只能输出受支持的组件类型和参数。

不能让模型返回任意HTML、JavaScript或Python并直接执行。

## 11.3 本阶段范围

优先完成：

- 等式天平。
- 等式两边共同运算的可视化。

# 十二、错题帮前端要求

**补救工作区**

保留当前Nova视觉主题。

不能为了展示AI能力堆积大量状态卡片。

必须处理：

- 空列表。
- 长题目。
- 长公式。
- 大图片。
- 上传中。
- OCR失败。
- 模型失败。
- 无法验证。
- 历史只读。
- 保存失败。

# 十五、必须执行的端到端流程

至少完成以下三条真实流程。

### 流程一：课程错题自动补救

教师发布任务 → 学生作答错误 → 自动形成错题 → 进入错题帮 → 查看原题和原作答 → 分析错因 → 分步补救 → 独立变式复测 → 返回原任务 → 教师查看记录。

### 流程二：个人拍照录题

学生进入错题帮 → 上传图片 → 裁剪 → OCR → 修改识别结果 → 保存题目 → 填写原始答案 → 分析错因 → 生成补救 → 完成变式练习 → 保存结果 → 退出登录 → 重新登录检查数据。

### 流程三：不同类型错题

连续选择三道不同知识困难的错题。

必须验证：

- 使用不同的补救内容。
- 变式题与原错题相关。
- 评分使用各自的参考答案。
- 不共享其他错题的补救上下文。
- 历史记录正确隔离。

这三条流程全部需要真实运行。
