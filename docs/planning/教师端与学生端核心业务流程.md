# 教师端与学生端核心业务流程

日期：2026-11-14。第一轮只补现有页面与链路，不重构全站导航。

## 资源管理员

资料与案例 → 上传材料 → 查看原文并修订识别文字 → 提取AI候选/新建案例 → 填写困难、诊断、具体教法及效果检查 → 标注来源类别、确认依据和许可 → 保存 → 人工核对 → 发布新版本。

发布后可修订或撤回；系统保存CaseVersion与原文引用。来源类型是管理者核对后的声明，不能拿审核按钮当外部教师身份认证。首次新建和旧未核验资源保留明确标识。

## 教师

1. 在现有案例检索中输入当前学生困难，并选择学科、年级、知识点；读取具体方法、适用范围与来源。
2. 可引用到已有备课；手动引用保留教师决定权，不自动变成“可信名师经验”。
3. AI备课选择已发布课时，填写教学任务/班级困难；沿用原六节点流程，使用同一来源与适用字段筛选规则。
4. 在“依据与核验”查看候选教法、选择理由、效果检查和原文链接；无可信候选时明确按课时生成。
5. 修改建议 → 确认用于备课 → 对照新旧内容 → 确认保存草稿。不会自动发布或更改学生已收到任务。
6. 通过原班级教学发布任务；通过原学情页回看学生作答、求助、复测及反馈。策略版本保存在原指导任务中，教师可追查当时使用的依据。

本轮真实联调覆盖资源审核发布、教师AI备课与显式确认；发布给学生的任务沿用已有隔离夹具，旧发布快照在案例修订后保持不变。不能把这一条称为“全新课程导入到全部课堂工具的全链路重验”。

## 学生

1. 登录本人账号，从原学习入口选择老师布置的内容。
2. 阅读课时或尝试作答；通过“问一问”描述哪里不确定。原答案与说明保存在Attempt，提示记录保存在原ModelJob/HelpRecord。
3. 服务端读取当前任务、题目、实际作答与相关历史，再检索、筛选经验，给提示及一个追问；界面折叠显示“本轮指导依据”，不默认堆内部ID。
4. 可要求举例、换讲法、补基础或独立尝试。继续指导时，真实的已核验独立困难记录会改变推荐；不把点击理解当作掌握。
5. 拍题后先核对识别文字。新图知识点尚未核对时，不冒用课时原题的困难或记忆结论，先通用指导。
6. 后续独立新题、我的错题、复测及教师反馈沿用原流程；帮助后正确与独立正确继续区分。
7. 模型失败使用既有任务重试与恢复；原作答和已保存草稿保留。

## 使用体验与后续安排

当前桌面入口仍为5175。只增加必要的来源表单和折叠依据，不增加新一套入口。第二轮再按真实任务调整“找优秀教法、我的备课、班级教学、学生学情”及学生四类工作入口；旧考试、课堂、题库、教研功能保持可达。第三轮才进行跨学科对照实验与功能层级精简。
