本机访问：http://127.0.0.1:8087。桌面客户端可用已有SSH端口转发访问该端口；服务当前绑定127.0.0.1。它加载Vite production dist并同源提供/api，不依赖Vite dev代理。MySQL端口23317，预发布独立库sczx_test_unit_preview_abdede；正常正式开发仍5177/8000。0013为既有schema，本步未新增表迁移。

配置模板deploy/release.env.example。实际配置在Git外0600文件/tmp/sczx-step16/release.env，数据/上传在/tmp/sczx-step16/uploads，构建快照在/tmp/sczx-step16/release/frontend，进程与日志在/tmp/sczx-step16/process。/tmp为当前验收位置，系统清理或机器重启可能删除；转长期使用须将配置、上传、MySQL数据、构建和进程目录放入持久目录。当前使用已有MySQL和Codex登录，不发布凭据。不具备宿主重启自动拉起保证，当前为可重启单进程预发布，尚未配置systemd常驻/开机启动。

复制模板到仓库外，填写已有可用MySQL、Python环境与绝对路径。依赖见backend-business/requirements.txt和frontend/package-lock.json。构建：`npm --prefix frontend run build`。设置SCZX_FRONTEND_DIST为对应dist，SCZX_MODEL_TRANSPORT=codex_cli，运行身份必须能访问已有Codex登录和CLI。运行：

```bash
/tmp/sczx-venv/bin/python deploy/manage.py start --env /tmp/sczx-step16/release.env
/tmp/sczx-venv/bin/python deploy/manage.py status --env /tmp/sczx-step16/release.env
/tmp/sczx-venv/bin/python deploy/manage.py stop --env /tmp/sczx-step16/release.env
```

start先执行项目既有migrate，再启动uvicorn和健康检查；失败保留日志。配置文件仅KEY=VALUE不执行shell。API在静态挂载前注册；hash路由刷新由同一index提供。会话Cookie本地HTTP设置Secure=false；只有实际配置HTTPS后才改true。服务同源无需额外生产CORS开放。预发布不启用自动建schema及调试重载；测试账号均明确自编验收，实际新建账号流程见release-smoke.json。

备份必须停该配置管理的写服务，确认没有其他进程连同一个库写入；等待模型任务完成或明确保留中断待重试后停止。输出目录必须是不存在的新目录：

```bash
/tmp/sczx-venv/bin/python deploy/manage.py backup --env /tmp/sczx-step16/release.env --output /absolute/private/backups/release-20261111
```

包含database.sql、uploads.tar.gz、release.json。release.json记录父仓提交、工作区是否有改动、实际前端index摘要及备份时间；开发时dirty=true的备份不能只凭父提交复现源码，须同时保留已验收源码和构建。目录0700，数据库凭据仅临时0600客户端配置，不出现在命令行。SQL、配置、上传备份不得提交Git。

恢复前用原MySQL管理员流程新建独立空库，填写另一个配置文件，指向空上传目录和独立进程端口。原库、原文件保留。执行：

```bash
/tmp/sczx-venv/bin/python deploy/manage.py restore --env /absolute/private/restored.env --archive /absolute/private/backups/release-20261111
/tmp/sczx-venv/bin/python deploy/manage.py start --env /absolute/private/restored.env
```

restore拒绝运行中的目标、非空库或非空上传目录。失败的目标保留用于调查，下一次改用新的空库/目录，不自动清库。模型任务保存在MySQL；被中断任务重启标失败后手动重试，已经成功的结果不重发。

本轮真实恢复两次，最终新库`sczx_test_unit_restore_aeeca8`，8088恢复验证后停止；原8087重新启动。共36表逐表行数/全行摘要一致、7个文件逐字节摘要一致；恢复后实际登录、五课提交、三题retest_passed、教师反馈及生产HTML可读取。[最终恢复证据](../verification/unit_20261111_v1/backup-restore.json)。保留本机原始私有备份路径，归档只包含摘要，不含SQL或原始用户数据。

更新顺序：保留当前Git版本及dist快照；停写→数据库与文件一致备份→隔离空库演练新版本迁移→准备新dist→迁移通过再启动→健康/新账号/图片/师生原始记录冒烟。迁移失败不继续启动新业务，不在原库试错，不自动降级：保留失败目标与日志，切回原服务版本及其对应未改动库/上传目录；如果原库已有部分迁移，只能从备份恢复到新的空库后再切配置。

前端回滚到保留的上一dist目录并重启服务。后端回滚在独立源码目录检出已验收版本，使用同一版前端及与该版本相容的数据库/文件快照，再按该版启动命令启动，不覆盖当前目录的未提交改动。**第十五步不理解本步应用题待人工核对标记，不能拿旧评分逻辑直接处理新增课程数据**；回滚必须恢复成对旧快照，保留新期间数据另行迁移，不丢弃任何期间作答。仅前端回滚也须验证接口和数据兼容。
