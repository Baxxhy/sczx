# 第十步使用与实现说明

日期 2026-11-10　版本 v1

目标：教学问题 → 案例检索与主辅引用 → 整体生成/局部改写 → 教师编辑 → 版本保存/恢复 → 学生预览 → DOCX导出 → 教师主动发布。沿用Vue 3 + JavaScript、Nova、现有FastAPI/MySQL、ModelJob与Codex CLI。只面向桌面Web。

## 使用

1. 教师进入“我的教案”，选择已发布课时。来源较旧时，阅读“使用发布课时”的替换提示，明确确认后采用当前版本。历史Agent仍可阅读，不能直接覆盖新课时。
2. 在“案例与版本”按教学目标或学生困难搜索，可筛知识点，阅读完整经验及原文，选择一个主要案例和辅助案例。引用保存固定案例版本；选案例本身不覆盖活动。
3. 编辑目标、学生基础；在“教学安排”编辑重点、难点、提问、可能回应、调整。活动可编辑标题、内容、顺序与活动级提问/回应/调整，例题和练习沿用原题目编辑区。
4. “AI备课”生成整个教案建议；“AI改写此活动”只改指定块，任务文本中填写改写方式。已有建议可局部重新生成，生成前内容保留在原任务及当前草稿历史。建议保存不会应用；确认窗口展示当前内容与新建议，可关闭或不采用；确认后写草稿。局部采用保留其他活动、目标、题目与个性化属性。
5. 保存后在“版本”查看时间、版本号及来源。可预览、导出或确认恢复旧版本；恢复生成新版本，不改旧版本。两页面并发时旧修订号返回409，先下载本地修改再重新读取。
6. 使用现有“学生预览”，无真实作答写入。导出当前草稿前会先保存，也可从历史版本导出该固定版本。教师另外选择班级、完成日期并主动发布；Agent不会发布，旧任务快照不变。

## 数据与接口

复用LessonDraft，新增revision和planning_details两个字段；教学安排及固定辅助案例放在planning_details；活动属性沿用blocks，题目沿用questions。新增lesson_draft_versions保存不可变JSON快照、单调版本号、原因与时间，唯一键(draft_id,number)。没有第二套教案或Agent。

- PUT /api/platform：教师行锁+乐观修订号；返回draftRevision；内容变动写历史，旧数据首次保存保留原始版本。
- GET /api/preparation/{lesson}/versions：本人教案历史。
- GET /api/preparation/{lesson}/versions/{version}：固定版本。
- POST /api/preparation/{lesson}/restore：明确confirmed及当前revision；保留旧版本并生成新版本。
- GET /api/preparation/{lesson}/export?versionId=…：导出选定快照；不传版本则导出当前保存内容。
- 原Agent任务支持rewriteBlockId，服务端从教师已保存草稿构建个性化输入；主辅参考固定版本进入现有案例/材料步骤。局部生成复用已有任务和队列，仍默认不重排。

确认时保留题目、学生基础、教学安排和引用；全量建议替换目标与全部活动的标题/内容，局部建议只替换目标活动。当前块属性保留。所有AI内容仍需教师审核，数学核验不覆盖完整讲解。生成内容的agentJobId仅供内部追溯，导出不显示内部ID或模型配置。

## 导出

复用既有python-docx，不新增运行依赖。DOCX包含标题、年级学科、目标、学生基础、重点难点、活动、提问回应、练习、参考答案、案例版本、资料位置、实际引用原文和教案版本。正文使用可编辑段落与标题；中文字体声明为微软雅黑，数学采用可读文字，未实现复杂OMML排版。

[样例](../exports/20261110_v1/教案导出样例.docx)已通过ZIP/XML校验、与选择版本逐块/逐题比较，以及临时副本编辑保存再读取。**Word/WPS实机显示与编辑未验证**：本机LibreOffice自身启动崩溃，无连接Word/WPS；用户答复暂时无法复核。不能把程序读取成功当成Office排版验收成功。

## 迁移、检查与回滚

安装既有依赖后，在backend-business执行 `python -m sczx_business.commands migrate`，0009迁移只新增两个字段与历史表。重复升级已由隔离测试覆盖。回滚须先停API、备份新增历史表及两个字段，再用Alembic downgrade 0008_knowledge_aliases；该操作会移除新增历史，不应在未备份的业务库执行。本轮没有回滚或删除业务库。

持久测试命令见backend-business/tests/README.md。隔离MySQL25项通过；无需MySQL的核心检查实际12项通过、13项明确跳过；前端Chromium5项、无外部服务1项通过。生产构建、导入、compileall、pip check和diff检查通过。保留Vite既有大包提示。

.github/workflows/checks.yml提供Python核心测试、导入/语法、前端无外部服务测试、生产构建及diff检查。本轮不推送，因此**远端Actions未执行**；MySQL与真实Codex/browser验收不冒充CI结果。
