## 决策树与分轮推荐

第一轮（无未决前置）：Q1课程→单元→课时，以等式性质首课为完整交付，其他单元课时为草稿；推荐是，层级简单且对应管理入口。Q2学生从班级任务学习、目录只读预览；推荐是，保持记录归属。Q3已有案例＋明确自编补充；推荐是，不编造公开教材与名师背书。按授权采用。

第二轮（依赖内容范围）：Q4稳定ID内容块，目标/讲解/例题/天平/随堂/独立题分开；推荐是，排序与记录不混淆。Q5两道随堂、两道独立、至少两道替换；推荐是，满足求助后新题。Q6知识点JSON前置ID有向关系与循环校验；推荐是，无需图数据库。Q7天平限非负实物量，加减乘除及乘零不可逆条件通过正确内容表达；推荐是。按授权采用。

第三轮（依赖结构）：Q8课时独立草稿与不可变版本、固定案例来源；推荐是。Q9新课时内容只由教师主动带入，提示替换教学内容但保留班级截止与学生基础，旧任务不重写；推荐是。Q10停用阻止新选用，既有任务继续阅读；推荐是。按授权采用。

第四轮（依赖版本）：Q11保留旧首课ID和记录，历史版本未知保持未知；推荐是。Q12两个不同课时真实验证防串数据，第二课验收自编标记；推荐是。Q13完成按必需块与检查提交，独立/正确另记；推荐是。按授权采用。

共同理解：管理编辑/核对/发布→教师选择正确课时版本备课→任务快照→学生按块学习、练习、求助及新题→提交→教师查看；修订不改历史。所有决策采用用户自动推荐授权，前沿已清楚，继续实现。

## 信息结构与任务

管理“课程内容”：课程目录/单元课时 → 内容/题目/知识关系/出处 → 学生预览/核对/发布。资料与案例入口保持独立。教师通过课程入口选择课时进入备课；学生课程目录展示已发布内容与匹配本课的任务。

1. 数据迁移：课程单元、知识点、课时草稿/版本、教案内容版本来源；旧外键保留。
2. 课时服务与首课内容：编辑、排序、依赖校验、数学检查、核对/发布/停用；初始化不覆盖编辑。
3. 多课时业务：平台选择、教案保存、任务发布、学生题目投影、逐块记录、随堂与独立检查。
4. 桌面工作台、目录及共享内容渲染器；预览隔离；动态题目/活动/标题与来源。
5. 隔离MySQL和账号验证两个课时、版本、数学、失败重试、刷新重启、三桌面尺寸与构建；交付并本地提交。

## 修订与边界

- 实际数据调查由只读代理完成；实现使用Vue JS与FastAPI业务路线，遵循用户迁移约定，没有回到旧仓颉/uni-app运行层。
- 新发布路径移除固定首课和默认题回填；已有教案与旧任务仍保留原始内容，未记录版本时不补造历史。
- 课时排序使用独立位置更新，不因调整目录生成修订内容；切换空课程清空旧编辑区，URL同时保存课程与课时定位。
- 浏览器脚本使用稳定题目ID定位作答，等待真实保存状态；跨账号使用完整页面加载。早期脚本误点第一题、未等待路由完成或未打开教师详情的问题已纠正，最后通过服务端实际记录及正确详情重新核对。
- 首课是项目自编示例；真实教师评审与教学成效没有条件验证，未声称完成。完整单元、独立自主学习实例、任意题型、完整Agent和错题补救扩展留后续阶段。
- 本步没有新增模型路径，没有为凑验收重新请求外部模型；已有Codex CLI gpt-6-luna/low能力保持。
