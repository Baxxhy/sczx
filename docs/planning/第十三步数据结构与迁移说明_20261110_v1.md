# 第十三步数据结构与迁移

2026-11-10，v1。

沿用 MySQL 业务表，增量迁移 `0011_wrong_remediation`，不新建第二套错题或模型任务系统。

| 实体 | 本次变化 | 关联 |
| --- | --- | --- |
| WrongQuestion | record_id 可空；新增 owner_id、details JSON | 课程来源保留 StudentRecord/Attempt；个人来源只有真实账号，不伪造任务 |
| WrongQuestion.details | source、subject、equation、originalPrompt、knowledgeIds、cropFileId、ocrJobId、confirmedText、cause/Confirmed、planJobId、draft | 原图继续使用 file_id，裁剪图单独 FileAsset；草稿按错题和实际 variantJobId 保存 |
| RepairAttempt | 新增 details JSON | 原错题、方案任务、实际变式任务/ID、不可变 equation/expected、phase、helped、requestKey、核验结果 |
| ModelJob | 无新增表或字段 | 复用 text，input.remediation/mode/wrongId；analysis、guidance、variant 共用队列、事件、失败重试与运行记录 |
| StudentRecord | 无新增字段 | drafts.blocks 保存互动动作/状态、解释与完成状态；课程作答、原帮助不清除 |

时间沿用服务现有 UTC created_at；前端本地显示。新错题所有者由会话确定；旧课程错题由来源记录回填。个人题图不随班级发布，教师只能读取有来源任务关系的错题和附件。

新提交采用实际变式任务 ID，不接受客户端参考答案。过去练习的参考值只随已作答历史返回；未作答题的 result 和 runs 隐藏 expected。

历史 RepairAttempt 的 details 为空时，读取时标记 legacy_fixed、原示例 z+2=9 及适用限制，数据库原值不变。旧结果不计入新版独立复测通过。聚合平台保存不会再重算或覆盖已有错题/补救。新增旧客户端无练习关联的数据只能记为未核对。

升级命令（先停写并备份当前库）：

```bash
cd backend-business
python -m sczx_business.commands migrate
```

隔离库验证真正的旧字段结构升级，并逐字段核对账号、任务、作答、错题及历史补救；日志见 verification/remediation_20261110_v1/migration.json。迁移不提供可能丢弃个人错题的自动 downgrade，需要回退时先导出新数据再人工恢复备份。

原始业务备份保存在本机私有临时文件，不上传仓库。主库升级结果以同证据目录 main-protection.json 为准，不用隔离结果冒充正式升级。
