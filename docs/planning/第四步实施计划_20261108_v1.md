# 第四步实施计划

日期 2026-11-08　版本 v1

## 目标和约束

把第三步 Vue 演示平台接入独立 FastAPI 业务服务与隔离 MySQL，让不同教师、学生账号在不同浏览器会话中读写同一条教学任务和关联学习记录。原图写入 sczx 专用本地文件目录；旧 localStorage 数据只在用户预览并确认后导入，作为历史演示记录保留。

按 grilling 访谈，用户已确认独立 MySQL、用户名密码与会话登录、预置角色账号、管理员建账号、教师建班、旧数据显式导入并保留历史演示归属。第四步不接真实模型调用；当前固定指导须标出演示状态。教师发布的教案和题目作为任务快照，修改草稿不回写已有任务。

遵循当前对 sczx 明确授权的 Vue 3/JavaScript + Python/FastAPI + MySQL 迁移约定。父级旧仓库 AGENTS 仅描述原项目，不能覆盖该迁移指示。开发中不读取、改写父级数据库目录与学生资料。实际验收使用 `/tmp/sczx-mysql` 的隔离数据目录与 `sczx` 库，没有连接父项目数据库。

## 内容模型与接口边界

核心关系：账号拥有一个角色；教师可以管理多个班级，班级包含学生成员；课程包含课时；教案草稿引用案例与课时；发布任务保存教案内容快照并关联班级、课时；每名学生在任务下有一份学习记录；学习记录包含进度、作答尝试、求助、错题、补救和教师反馈；上传文件先成为文件资源，再按用途关联案例或错题。

页面结构采用角色入口：未登录进入登录页；已登录后按账号角色进入学生学习、教师教学或内容管理。班级/任务/案例等对象通过真实 ID 定位；不再通过本地“空间切换”模拟角色权限。首轮验收可用管理员创建账号，再由教师创建班级并添加学生账号。

页面经 `frontend/src/services/api.js` 访问后端：账号、班级、案例、任务发布、学生反馈、文件与旧数据导入使用资源接口；当前已接入页面读写复用 `/api/platform` 聚合端点，由服务层在 Pinia 与学生记录映射间保持同一对象。后端返回业务 JSON，不直接序列化 ORM；登录、账号、班级和发布输入使用 Pydantic 校验。原图经文件资源接口保存，业务记录保存文件路径，不反复存储 base64。

## 实施顺序与完成证据

1. **工程与本地基础。** 在 sczx 增加 Python 业务服务、环境变量样例、依赖清单、Alembic、启动/初始化入口、MySQL 与本地文件配置。准备仅用于本轮的临时 MySQL 数据目录和单独端口。完成证据：数据库服务、FastAPI health、数据库 health 均可单独检查；不会连接其他数据库。
2. **实体与初始化。** 建立账号、班级、成员、课程、课时、案例、教案、任务快照、学生记录、作答、求助、错题、补救、反馈和文件资源模型。迁移命令可重复；初始化不重置已编辑内容。预置账号凭据只从环境配置，公开文档不放密码。完成证据：迁移后按 ID 读取并核对实体外键关系。
3. **认证、角色与班级。** 实现用户名密码登录、服务端会话、当前用户、退出、角色依赖、管理员账号管理、教师建班及添加学生。完成证据：用不同 HTTP 会话登录不同角色；未授权角色调用接口收到明确拒绝；教师只看到自己班级。
4. **课程内容、案例和教案。** 将当前课程、种子案例和教案草稿写入数据库，提供列表、详情、更新和管理端发布。保存、刷新、重新登录后可恢复。完成证据：案例管理端发布、教师端读取并带入教案，教案修改后从独立会话再次读取。
5. **任务与首课学习 API。** 发布事务创建不可变的教案/题目快照，并为每个班级成员建立独立任务记录。学生端读取任务详情、保存讲解进度、解释、天平状态、草稿、帮助、作答、错题、补救和提交；教师学情从真实记录读取并写反馈。完成证据：教师发布、学生完成、教师查看、学生查看反馈的完整数据链关联一致；再次发布创建新任务而旧快照不变。
6. **文件上传与恢复。** 保存原始图像到 sczx 专用目录，数据库记录文件名、类型、大小、存储 key、创建者和关联；服务通过授权读取接口返回文件。完成证据：上传图像、绑定错题、重启 API 后从新会话读回同一原图；无效文件及文件缺失均显示错误并可恢复。
7. **旧数据显式导入。** 前端预览当前浏览器可迁移记录的数量与类型；由管理员确认后调用批量导入接口；旧学生/班级使用固定的历史演示实体和来源标记，绝不归到真实账号；基于旧 ID 识别重复导入。完成证据：导入前后计数匹配、第二次导入不新增、原 localStorage 未删除、导入错误可以逐项查看并重试。
8. **前端切换与视觉检查。** 建立登录页、角色信息和退出入口，改造所有页面数据访问方式，去除实际使用中的自动聚合 localStorage 写入；保留旧数据导出和显式导入。为加载、空状态、保存失败、会话失效、上传失败、重复操作、无效详情提供可操作反馈。桌面、平板、手机检查受影响页面，沿用现有深色文字和当前卡片布局规范。
9. **全流程验收与交付。** 构建前端并实际启动 API/MySQL，使用相互独立的浏览器会话或隔离存储完成初始化、案例发布、备课、任务发布、学生求助/作答/错题补救/提交、教师反馈、学生查看。检查 MySQL 关联、文件内容、重登/重启恢复、重复导入和失败重试。按项目约定不新增持久测试目录、样例、测试配置或专用测试依赖；必要的临时验证脚本放在 `/tmp`，以真实 API 调用、SQL 查询和浏览器证据验证。

## 完成状态与证据

- **工程与数据库：完成。** `backend-business/` 提供依赖、环境配置、FastAPI、SQLAlchemy、Alembic 与启动命令；隔离 MySQL 8 实例通过 `/api/health` 检查。迁移 `0001_initial` 与 `0002_file_links_and_supplements` 均已应用。
- **账号、角色与班级：完成。** 浏览器确认管理员创建教师/学生账号，教师新建班级并加入学生；教师、学生使用独立会话登录。
- **案例与教案：完成。** 内容草稿可保存、发布；教师草稿首次编辑会写入数据库；发布任务保存课程活动与题目快照。
- **学生学习与教师反馈：完成。** 不同账号在数据库中读写同一任务的解释、求助、两次作答、错题、补救、提交与反馈；教师重新读取后看到记录，学生新会话可查看反馈。提交状态不会被稍后的普通保存回退。
- **文件与旧数据：完成。** 上传题图写入文件资源表和本地存储目录，并从另一个教师会话授权读取；历史导入保留原 localStorage，落到停用的历史演示学生，重复导入不重复写入。导入保留旧时间字段并先建立错题再关联补救。
- **前端：完成。** Pinia 加载时将教师当前选择的学生记录映射为同一对象，确保学情页、结果页和 API 保存使用一致记录。调整教师学情汇总、班级成员加载、发布班级选择和实际操作状态。
- **验证：完成。** 前端 Vite 构建、Python compileall、差异空白检查通过；浏览器全流程验收无脚本异常；临时浏览器数据和 MySQL 仅用于本轮验收。

本轮运行环境中曾遇到浏览器模拟器仅改 DOM 而不更新 Vue 模型的情况，验证已改用 CDP 键盘输入；也发现并修复了学生记录映射、提交状态回退和历史补救外键顺序问题。

## 后续步骤边界
