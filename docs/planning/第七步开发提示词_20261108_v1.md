1. 明确课程、单元、课时的 ID、顺序、状态及关联；按现有规模选择普通列与 JSON，不建立不必要的通用内容平台。
2. 管理端可新建、编辑、排序、保存与重新打开课程目录；课程页不再指向资料案例编辑器。
3. 课时包含年级、学科、目标、前置知识、预计学习时长、正文块、题目及案例引用；未知信息不编造。
4. 知识点保存稳定 ID 和名称，支持前置关系编辑、重复边与循环检查，并在课时中选用。
5. 首课前置知识至少围绕相等关系、基本运算及算式含义组织；后续“解简单的一元一次方程”等课时可建立真实目录草稿和依赖。
6. 草稿课程/课时不能伪装成已开放内容；空单元、未发布和没有任务分别有明确结果。
7. 新增迁移兼容原课程、课时和任务外键，重复初始化不能覆盖人工编辑或重复生成版本。

### 六、建设课时编辑与预览工作台

采用目录、当前课时编辑、学生预览的清楚结构。复用可调整分栏和现有编辑能力，不把右侧永久留成大块空白。

- 内容块至少支持讲解、例题、互动活动、练习与独立检查；保留稳定块ID、类型、顺序及必要目标关联。
- 支持增删、排序、编辑、保存、切换课时及重新读取。删除需提示后果，拖拽同时提供键盘可用的上移/下移操作。
- 教师提示、参考答案、判断依据与学生可见内容分开，避免任务问题数据使独立检查提前暴露答案。
- 学生预览复用真实学习渲染组件；预览与真实作答隔离，不写入学生学习记录。
- 数学公式、图文、长内容与已有天平可正常显示；缺图与不支持块类型有明确反馈。
- 保存中、失败、重试及未保存切换有明确行为；轮询、路由刷新或迟到的响应不能覆盖当前课时未保存输入。
- 案例选择能浏览已发布版本及出处，移除或更换案例有清楚结果；多案例需求按访谈结果实现，不用复杂通用引用系统扩大范围。

### 七、完成等式性质首课内容

录入可直接学习的完整首课，不只给出标题和占位段落。

1. 明确学习目标、必要前置知识、活动顺序和完成条件。
2. 从相等关系引入，用适合的天平活动展示两边共同变化，要求学生观察并解释。
3. 讲解等式两边同加或同减同一个数的性质，例题覆盖变形前后相等关系。
4. 讲解同乘同一个数，以及同除以同一个非零数的性质，清楚呈现除数不能为零。
5. 区分“等式仍成立”和“变形与原方程等价”：乘零可能损失解的信息，不能据此宣传任意可逆。
6. 题目包含题干、目标、答案、必要解释、判断规则及提示；随堂练习与独立新题不能只是复制相同数字。
7. 对常见错误提供真实对应的反馈，如只改一边、两边变化不一致、除以零和运算错误；不要把所有错误统一显示“粗心”。
8. 求助后记录当次获得帮助，换新题建立独立尝试，题目不足时明确显示而非循环冒充新题。
9. 每个自动判定题核对等价答案及无法判定的输入；不能解析的解释或图片不得直接记为错误或正确。
10. 保存公开材料/案例出处与自编补充标记，数学结论经程序及项目成员核对；无人实际教师评审时不得标注名师审核。

### 八、发布、版本与师生联动

- 发布前检查必需内容、题目完整性、块ID唯一性、活动配置、数学条件与案例版本有效性；反馈精确到具体课时或字段。
- 发布生成不可变内容版本；草稿变化不提前影响学生目录、教师选用与既有任务。
- 教师从课时进入备课，带入正确内容版本、目标、活动、题目与案例来源，允许继续编辑。
- 清理默认取第一个课时和写死 `lesson-equation` 的新建路径；路由、API、状态与任务按实际ID对应。
- 任务标题、课时ID、内容块及题目来自教师本次发布内容，学生读取任务快照；不能退回全局默认题或另一个课时。
- 修订课程后，旧任务、原作答、帮助、错题和反馈继续关联原题与原版本；新任务可使用新版本。
- 保留旧书签和历史记录的明确结果。不能还原的旧来源如实未知，不伪造追溯数据。
- 本步完成内容接入必需的备课与学习适配，不提前重做完整Agent编排、考试、课堂、教研社区或学习记忆系统。

### 九、视觉与文案验收

沿用 Nova 主题，桌面页面需要清楚、精致且真正适合阅读和编辑。

- 课程封面、概要、目录、学习目标和主操作形成明确层级；有真实内容才展示，避免单张横向巨卡右侧大片空白。
- 1440、1920、2560分别检查栏宽、内容密度、行长和主操作位置；空间通过合理分栏与内容组织利用，不靠重复说明填充。
- 正文、表单值、状态和按钮文字不能过浅；错误、必填和选中状态清楚。
- 删除口号、重复标签、说明段落与装饰性微文案；必要补充用 info＋tooltip。
- 保留必要表单标签、可访问名称、焦点，以及发布、停用、删除和替换内容的后果提示。
- 动效轻量，尊重减少动态效果偏好；下拉、弹窗、长公式、图片和拖拽不出现遮挡或不可操作区域。
- 空列表、搜索无结果、首次进入、加载、保存失败、失效ID与历史版本都有与业务相符的状态。

### 十、实际验证与交付

至少通过下列真实操作，不以页面出现、提示成功或构建通过代替业务闭环：

1. 管理员建立/打开课程、单元与首课，编辑知识前置、内容、练习、独立新题及案例来源；保存后刷新恢复。
2. 实际增删、排序并保存内容块，预览与学生渲染一致；预览操作不产生真实学习成绩。
3. 核对数学与发布信息后发布首课，学生课程页和教师课时入口读取相同发布版本。
4. 教师从正确课时备课、预览并向隔离演示班级发布；学生账号从任务进入学习，完成活动、练习、求助、换题及提交；教师读取相应记录。
5. 第二个课时使用不同标题、内容和题目，验证编辑、发布、任务与刷新不会串到首课；演示内容明确标注。
6. 修订首课再发布，旧任务与旧作答保持原版本；新任务能采用新内容；被停用内容的历史访问符合确认规则。
7. 验证未发布课时、无可替换题、非法活动配置、除零、循环前置关系、失效ID和保存失败后的重试。
8. MySQL迁移、重启恢复及初始化兼容实际通过；验证隔离数据，不删除原数据或覆盖真实学习记录。
