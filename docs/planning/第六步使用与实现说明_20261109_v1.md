# 第六步使用与实现说明

日期 2026-11-09　版本 v1

本步提供桌面 Web 的原始材料、定位片段、结构化教学案例及发布版本管理。模型继续通过 Codex CLI 使用 gpt-6-luna / low；PDF/Word解析为普通CPU程序，不部署本地模型。

## 安装与升级

沿用第五步的独立MySQL、账号、文件目录和CLI配置。先安装当前依赖并停止业务API，再在 `backend-business` 目录执行迁移和初始化：

```bash
python -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python -m sczx_business.commands migrate
.venv/bin/python -m sczx_business.commands seed
.venv/bin/python -m uvicorn sczx_business.main:app --host 127.0.0.1 --port 8000
```

已有虚拟环境直接安装更新，无需重新创建。新增依赖为 PyMuPDF 和 python-docx；所有依赖由 pyproject.toml 管理。最新迁移 `0006_materials_case_versions` 增量建立材料、片段、案例草稿和版本表，并增加教案来源快照。旧发布案例保留为历史版本，旧任务不被重写；重复seed不会增加重复案例版本。旧教案缺少案例版本时不补造历史，参考区明确按当前发布内容阅读，重新使用案例后才固定版本。

在项目根目录运行：

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

访问 Vite 输出的地址，默认端口5177，API默认8000。生产构建 `npm --prefix frontend run build`。API按单worker运行；MySQL和原文件目录均需保存。CLI可执行路径、隔离配置目录和外部上游沿用第五步说明，不使用备用OPENAI凭据。

## 管理端操作

1. 打开“内容工作台”，点击“上传材料”。填写标题、作者或机构、来源链接或说明、年级与学科，选择原文件并上传。未知作者可留空，不自动编造。
2. 支持PDF、DOCX、PNG/JPEG，文件最多30MB。PDF最多30页，Word最多300个正文片段，超出时拆分上传；失败原件保留。
3. 左侧列表显示材料与处理状态。中间查看原文位置：PDF是真实页码，Word为段落/表格/插图位置，图片为整图。点击原图可打开大图，“原文件”下载上传时的原始字节。
4. 文字PDF按页提取，扫描页独立进行Codex识别；混合PDF按页判断。Word按正文顺序保留段落和表格，插图独立保存与识别；检测到公式时提示对照原件。Word阅读视图不承诺还原原排版或分页。
5. 切换“识别文本”修订文字并保存。后台轮询不会覆盖未保存的输入；修订记录和最初提取文本分开保存。选择材料与原文位置的URL可以重新打开和刷新。
6. 在“整理范围”选择片段，每次1至8处、合计不超过24000字。选择可跨材料保留，使用“清空选择”重置。点击“提取为新案例”，后台调用Codex，成功后打开独立案例草稿；不会覆盖已编辑案例。长材料分批整理。
7. 也可“手动整理”：正文、教学经验、出处分开编辑。出处可以关联左侧所选原文，为引用选择对应内容并修改摘录；发布时核对摘录确实来自原文或已保存的修订文本。
8. 保存后勾选“已对照原文核对内容”，预览教师最终阅读效果，再确认发布。编辑任何内容后，原人工核对状态撤销；相关数学核对标为需重新核对。教学经验页可新增、删除或修订最多12组核对表达式，重新计算后仍需人工确认。保存与发布期间暂时禁用编辑，避免重复操作。
9. 已发布案例只读；“创建修订”开启独立草稿，新草稿不会进入检索。再次发布形成新版本，旧版本保留；版本列表可预览历史内容。同一草稿并发发布或网络重试返回相同版本，不重复创建。
10. 撤回需要确认：停止进入新检索，但历史发布版本、原文和既有教学任务引用保留。不提供物理删除原文件或历史版本的操作。

材料与案例均有独立ID，支持一份材料整理多案例以及一篇案例关联多个原文位置。当前课程内容入口复用资料编辑组件；课程、知识关系和完整课时管理按第七步继续建设。

## 提取、引用与数学检查

新增 `document_parse`、`document_ocr`、`case_extract` 三类后台能力。普通解析、每个识别页面和每次案例提取分别有独立任务，复用现有MySQL任务/执行记录/SSE、超时和重试。

案例提取结构包括知识点、目标、学生基础与困难、引入方法、步骤、提问、可能回应、调整策略和适用边界。模型额外建议单独标示。每个非空教学字段及数组中的每一步都有field引用，记录材料位置与逐字摘录；Pydantic结构与服务端摘录/字段覆盖检查不通过时不会生成有效案例草稿。

SymPy只核对结果中列出的表达式，不能证明整篇教案或教学结论正确。详情和预览可展开具体等式及核对状态；人工编辑后撤销旧核对结论，可将核对项修订为纯数学表达式后重新计算。材料与模型结果仍需项目成员对照原文审核，不冒充教师认证。

## 教师与学生

发布后立即进入当前BM25检索，结构化经验也用于匹配。教师按案例ID阅读正文、经验字段与原文依据，可点击对应PDF页、Word段落或图片位置；按版本ID打开历史案例。

“用于备课”保存选中版本的完整案例快照并带入教学活动，不清空其他活动。教案参考区显示实际所选案例、版本和原文；教师发布任务时再次保存该版本快照。后续案例修订和撤回不改写已发布任务。

学生指导检索当前有效发布版本，将教学经验与来源快照交给Codex；指导记录和教师回看显示案例版本及原文位置，并区分课时关联的历史案例与当前检索结果。旧指导继续读取原结果，不用当前案例覆盖历史。撤回案例不再进入新的检索，但旧版本原文仍可解释与回看。

## 恢复与页面状态

- 解析按位置提交；服务中断保留已完成片段。重启后中断任务显示可重试，重试跳过已完成位置，不覆盖其人工修订。
- 识别失败可在对应位置重试；其他已完成页不重新调用模型。案例提取失败保留已有草稿，重新提取生成新草稿；左侧“整理任务”可重新打开、查看执行记录并重试，任务URL支持刷新恢复。
- 模型每次CLI调用最多115秒，每次任务执行最多150秒；可恢复错误最多自动重试2次，之后手动重试。
- 处理进度保留实际预计片段总数，来自真实任务步骤与已完成片段数量，不以固定动画冒充完成。
- 无文件、未知材料/案例/位置、空正文、未核对发布、引用不匹配与解析失败均返回明确状态。工作台更新URL定位不重建整页，保留当前编辑交互。
- 新鲜独立数据库已验证迁移和重复seed；现有sczx数据库账号不需要额外建库权限。安装时由部署者准备业务数据库。

## 主要数据与接口

新增表 `source_materials`、`material_units`、`case_draft_contents`、`case_versions`；教案新增 `case_snapshot`。既有 `TeachingCase` 保留当前发布内容与状态，供原接口兼容。发布内容只由版本发布路径更新，旧聚合自动保存不再写入案例。

|接口|用途|
|---|---|
|GET/POST /api/library/materials|材料列表、原文件上传并排队解析|
|GET/PUT /api/library/materials/{id}|材料详情与来源信息修订|
|GET/PUT /api/library/units/{id}|原文定位、识别文本修订|
|POST /api/library/extract|按所选原文提取新案例|
|GET/POST /api/library/cases|管理列表、手动创建草稿|
|GET /api/library/cases/{id}|草稿、当前发布内容与版本列表|
|PUT /api/library/cases/{id}/draft|保存草稿，修改后撤销核对|
|POST /api/library/cases/{id}/review|记录人工核对|
|POST /api/library/cases/{id}/verify|重新核对列出的数学表达|
|POST /api/library/cases/{id}/publish|发布不可变版本|
|POST /api/library/cases/{id}/revise|创建修订草稿|
|POST /api/library/cases/{id}/withdraw|停止新检索，保留历史|
|GET /api/ai/cases/{id}?versionId=...|当前或指定历史发布版本|

原任务详情、SSE与重试接口继续使用。旧案例没有上传原文时如实标为历史案例，不补造作者、页码或定位。

验收使用了明确标注的自编材料；真实公开材料可通过相同入口录入。未实现旧DOC转换、任意网页批量抓取、音视频解析、图片局部框选、完整Word排版和移动端。完整课程建设、长语料索引与Agent编排按后续计划推进。
