# 第五步使用与实现说明

日期 2026-11-08　版本 v3

状态：按用户要求采用替代方案，仅以桌面 Web 为交付目标。教学模型继续使用 Codex CLI；检索改用 BM25，语音改用浏览器输入和朗读。无需本地模型。完整证据及浏览器限制见[第五步实施与验收](第五步实施与验收_20261108_v3.md)。

## 安装与运行

前端 Vue 3 + JavaScript，业务服务 FastAPI + MySQL。安装方式及独立数据库配置沿用第四步；本步新增 HTTPX、SymPy，执行 `pip install -e backend-business` 安装清单内依赖。

安装本机 Codex CLI，以运行后端的账号完成登录和模型可用性检查。业务服务固定调用 `codex exec -m gpt-6-luna -c 'model_reasoning_effort="low"'`，通过标准输入传教学内容，图片通过附件传入，使用 JSON Schema 约束输出，不把教学输入拼入 shell 命令。

`backend-business/.env` 中的主要设置：

```dotenv
SCZX_MODEL_TRANSPORT=codex_cli
# 可选；默认从 PATH 找 codex
# SCZX_CODEX_BIN=/absolute/path/to/codex
# 可选；相对路径以 backend-business 为基准
# SCZX_CODEX_HOME=./var/codex
# 默认不继承终端代理；需要时显式开启
# SCZX_CODEX_INHERIT_PROXY=true
```

默认使用 CLI 自身配置与登录。若已有兼容 Responses 的外部上游，可以复制 `backend-business/config/codex.example.toml` 到忽略的 `backend-business/var/codex/config.toml`，填写服务地址和凭据环境变量名，然后设置 `SCZX_CODEX_HOME`。密钥只写本地忽略环境，不提交。当前验收环境使用该隔离配置连接原已授权主服务；不使用备用 OPENAI 凭据。

当前默认路径不读取旧 HTTP 模型池，不会自动回退到 HTTP；旧适配源码和历史结果保留，当前三类能力统一通过 CLI。

升级先停止 API，在 `backend-business` 目录执行：

```bash
.venv/bin/python -m sczx_business.commands migrate
.venv/bin/python -m sczx_business.commands seed
.venv/bin/python -m uvicorn sczx_business.main:app --host 127.0.0.1 --port 8000
```

工作循环位于单个 API 进程，使用单 worker；`seed` 保留既有内容。另一终端在项目根目录执行：

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

访问 Vite 输出地址，默认 5177，`/api` 代理到 8000；可用 `SCZX_API_PROXY` 调整代理。构建：`npm --prefix frontend run build`。模型请求上限 115 秒，任务整体上限 150 秒；超时和取消回收 CLI 子进程，服务重启按既有任务恢复规则处理。

## 当前功能

|入口|实现|
|---|---|
|学生文字指导、题图识别|Codex CLI，固定 gpt-6-luna / low，保留题图修订确认|
|教师案例搜索|后端 BM25 检索已发布案例的标题和正文，无向量依赖|
|教师语义排序、管理端案例检索|BM25 召回后可选 Codex 语义重排，保留任务记录|
|学生指导关联案例|根据问题检索最多三篇案例，将正文快照交给模型，结果保留案例名称及来源|
|语音输入|浏览器 SpeechRecognition，追加确认后的文字；临时识别文字只展示，不自动发送|
|文字朗读|浏览器 speechSynthesis，支持暂停、继续、停止；不生成可下载音频文件|

BM25 使用 Unicode 规范化、中文二元组和英文/数字/运算符词元，参数 k1=1.5、b=0.75；标题按两份加入词频，正文按一份。只返回正分匹配，不匹配时显示空结果。当前案例规模较小，每次查询读取已发布内容并在内存计算；不新增向量数据库、全文索引或分词依赖。BM25 是词汇相关检索，不承诺理解所有同义表达。

## 教师与学生操作

1. 教师打开“教学案例”，输入知识点或学生困难，得到 BM25 结果；需要时点击“语义排序”。模型重排失败时保留 BM25 结果并显示提示。
2. 点击“阅读案例”，按案例 ID 读取实际正文。刷新保留当前案例；不存在或未发布的案例显示返回入口。点击“用于备课”带入选中的案例内容，不替换已发布任务快照。
3. 发布任务后，学生按既有学习、独立检查、补救与提交流程操作。学习助手会将相关已发布案例快照加入指导请求；教师可回看对应指导和关联案例。
4. 在学习助手点击“语音输入”，允许麦克风后说出问题。确认识别文字追加到原输入框，可编辑，再由学生主动发送；不自动提交题目或作答。
5. 语音输入后的问题沿用学习记录草稿保存，刷新恢复。切换任务或题目、页面离开、输入被禁用时停止识别，避免将旧回调写进新题。
6. 指导结果可“朗读”。未展开讲解时只读当前提示；展开后可读分步内容。案例详情也有朗读入口。文字改变、开始另一处朗读或页面离开时停止旧朗读。
7. 教师继续查看学生原图、确认题目、指导、作答和补救，并保存教师反馈；原有结果和原图不删除。

## 管理端

“反馈与运行 → 模型与任务”当前六个入口是：文字指导、题图识别、案例检索、材料重排、语音输入、文字朗读。

- 案例检索读取真实已发布案例；勾选“语义重排”时继续调用 Codex。运行结果保留材料正文快照、BM25 分值、是否重排和所用模型。
- 材料重排仍可输入自选候选材料，通过 Codex 进行结构化排序。
- 语音输入与文字朗读直接使用当前浏览器，不创建假后端模型任务，不把朗读伪装成合成文件。
- 旧 Embedding、上传音频转写与 TTS 任务保留在历史列表中，可查看原结果和已有文件；当前主入口采用替代方案，不再重试 CLI 不支持的旧任务。
- 原来上传音频后的转写修订接口仅用于查看和修订历史成功记录，不代表浏览器语音输入支持任意录音文件转写。

## 浏览器条件与回退

语音输入需要浏览器支持、麦克风权限及浏览器语音服务可用；有些浏览器会将音频交给其在线识别服务，不保证离线可用。无法识别、权限拒绝、无麦克风、无结果或连接失败时，显示就近提示，保留文字输入。设备声音列表需包含可用中文声音才能朗读中文；缺失时继续文字阅读。

当前服务器的无头 Chromium 有语音接口，但中文声音列表为空；原生朗读检查确认能提示并回退。当前原生识别检查使用公开音频作为虚拟麦克风输入，返回网络错误，页面保留文字输入。真实声音输出和真实麦克风识别仍需在具有对应能力的桌面浏览器验收。受控浏览器事件验证了输入追加、暂停、继续、停止及错误处理，不作为实际识别或发声成功的证据。

## 接口、任务与数据

- `GET /api/ai/search?q=...`：检索已发布案例；空查询列出全部，查询无匹配返回空列表。
- `GET /api/ai/cases/{id}`：读取已发布案例，找不到返回 404。
- `POST /api/ai/jobs`：新增 `retrieval` 能力，数据为 `query` 和可选 `rerank`；材料由服务端读取并保存快照，不采纳客户端伪造的案例库。
- 既有作业列表、详情、重试、SSE 事件与历史 ASR 修订接口保持。教师能读取自己的检索任务及其班级的学生指导任务。
- 文本指导输入的 `context.teachingCases` 保存关联材料快照；成功结果的 `sources` 保存案例 ID、名称和来源。

沿用 MySQL 任务、执行尝试和事件表，本轮无需数据库迁移或新增依赖。模型任务后台继续，页面刷新读取结果；运行中输入去重，失败最多自动重试两次，后续手动重试。检索任务若语义重排失败，以真实 BM25 结果完成并显式显示降级提示，不冒充模型重排成功。

浏览器语音遵循浏览器生命周期，离开页面即停止；学生确认后的文字按业务草稿保存。管理端语音框仅作当前页面能力检查，不是上传录音归档服务。

## 范围

本轮替代了原来被向量和语音 API 配置阻塞的主入口。原始“六类外部 API 全部真实调用”目标与当前方案不同，不将 BM25 算作 Embedding，不将浏览器语音算作后端 ASR/TTS API 验收。完整经验库加工、长文档分块、复杂 Agent 编排和录音文件批量转写仍属后续工作。
