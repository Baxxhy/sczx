重点澄清以下产品决策，并按实际依赖安排轮次：

- **首条验收闭环与材料样本。** 推荐以七年级“等式性质”相关材料完成从上传到教师使用、学生指导的闭环；演示材料和真实公开资料清楚区分，不编造作者与教师背书。用户未提供样本时，可推荐寻找可访问的公开小样本或使用明确标注的自编验收材料。
- **首版格式。** 推荐支持文字 PDF、扫描 PDF、DOCX、PNG/JPEG；旧 DOC、批量网页抓取和音视频解析暂不纳入。文件大小、页数和一次处理范围根据实际环境提出可运行的限制，再确认，不承诺无限文件。
- **材料与案例关系。** 推荐一份材料可整理多篇案例，一篇案例可关联多处原文；原文件和定位记录独立保存。
- **提取与发布。** 推荐模型只生成草稿，项目成员对照原文修订后主动发布；没有依据的字段留空或标记待核对，不由模型编造。
- **案例修改与既有引用。** 推荐草稿和已发布版本分离，修订发布生成新版本；教师已发布任务与既有学生指导保留当时快照。
- **原文定位。** 推荐 PDF 保存实际页码，DOCX 保存段落或表格位置，图片保存图片定位；不把 DOCX 段落号伪称固定页码。是否需要本步实现图片局部框选，依据用户要求进一步确认。
- **失败恢复。** 推荐按页或片段保存中间结果，失败后只重试未完成部分；替换原文件或重新提取前保留已有人工编辑内容。
- **发布与撤回。** 推荐 BM25 只读取当前有效发布内容；撤回后退出新检索，既有任务、指导与原文历史引用仍可解释和回看。具体撤回交互与历史可见范围需确认。

推荐用于帮助用户决策，不预先写成“已经确认”。实际发现新的重要依赖时继续追问，常规代码组织与成熟库选择由你调查后合理决定。

### 三、技术与产品约束

- 只做**桌面 Web**，主要检查 1440、1920、2560 宽度、浏览器缩放和鼠标键盘操作，不开发手机端或原生应用。
- 前端 **Vue 3 + JavaScript**，业务源码为 `.vue`、`.js`，不引入 React、TS/TSX 或 TypeScript 工程配置。
- 沿用 Vite、Vue Router、Pinia、Tailwind、shadcn-vue / Reka UI、Lucide、motion-v 和现有 Nova 主题；需要可调整双栏时优先复用现有 Splitter。
- 业务服务 **FastAPI + MySQL**，原文件继续保存到既有文件存储，数据库保存关联与处理状态；不引入第二套业务数据库。
- 所有需要模型的调用通过**本机 Codex CLI，固定 `gpt-6-luna`、`low` 思考强度**。复用现有项目配置与子进程适配，不另接一套默认 HTTP 模型请求，不使用已被用户拒绝的备用 OPENAI 凭据。
- 文档解析、页面渲染、BM25、SymPy 属于普通程序能力，可以使用成熟库；不部署本地 OCR、Embedding、语音或大语言模型。
- 检索继续使用 **BM25＋可选 Codex 语义重排**，不恢复 Embedding、Qdrant 或向量数据库前置条件。
- 项目追求简单可运行；优先一个业务服务与现有任务循环，不为本步新增 Redis、Celery、分布式调度或费用管理。
- 保留现有原图、材料、数据库、历史任务和其他未提交改动；不重新搬回父目录旧运行层，不依赖父项目源码才能启动。

### 五、材料上传、解析和原文阅读

依照访谈确认的格式和限制实现真实处理，不以保存文件名或显示固定正文代替解析。

1. 管理端支持上传、填写来源信息、查看处理状态和重新进入材料详情，多个文件分别有独立 ID。
2. 保存原始文件、文件类型、名称、作者或机构、来源链接或说明、适用学段与学科、上传时间。来源未知时允许明确标记，不编造信息。
3. 文字 PDF 优先用解析库提取文本；扫描页渲染为图片后通过 Codex 图文能力识别；混合 PDF 按页判断，不把整份文件一律当图片处理。
4. DOCX 按顺序读取段落和表格；图片材料保留原图。公式、表格或文字无法可靠还原时保留原文位置和核对状态，不静默丢弃或自动判为正确。
5. 原文预览与提取结果可以对应查看。PDF 能跳到实际页，DOCX 能定位段落或表格，图片能打开对应原图。
6. 解析结果按页或片段保存，可修订识别文本；修订后的文本与原始提取结果可区分。
7. 文件不存在、解析失败、文件没有可提取内容、部分页面失败时，显示实际状态及可用操作；原文件仍可回看。

选用库前先检查现有依赖和能力。Word 原文无法在浏览器直接展示时，可以采用原文件下载与按段落还原的阅读视图，但要说明它与原始版式的区别，不展示伪造的 PDF 页码。

### 六、结构化教学经验与数学核对

围绕真实教学内容提取，而不是只生成一段摘要。

结构至少覆盖：案例标题、适用年级和知识点、教学目标、学生基础与困难、引入方法、讲解步骤、教师提问、可能回应及调整策略、适用边界，以及对应原文位置。

- 每个有原文依据的教学片段保留材料 ID、位置 ID 或页码、原文摘录；模型建议与材料原文有清楚区分。
- 模型输出用 Pydantic 校验。现有数学题 OCR 与指导 Schema 不足以承担整页资料和教学经验提取时，新增明确的业务 Schema 与调用入口，不用改提示词冒充不同结果结构。
- 长材料按页或片段处理后汇总；保留中间结果与当前进度，明确处理现有 CLI 与任务超时限制，不建立一个必然超时的整本解析任务。
- 对可计算的数学表达调用现有 SymPy 能力；输出已核对、不一致或需核对，保留适用范围。不得把少量等价式检查扩展成“整篇案例已验证”。
- 自动提取不覆盖人工修订；再次提取时提供保存为新草稿、选择覆盖范围等已确认交互。
- 支持人工修订结构化字段与可读正文，教师阅读时呈现自然连贯的案例，不展示模型 JSON 或后台任务术语。

### 七、案例编辑、发布与版本

将当前基础案例编辑升级为可管理多篇案例的真实业务。

1. 材料、案例和处理任务之间有清楚关联，一份材料可以产生多个草稿，重新打开能找到正确草稿。
2. 编辑器支持可读正文、结构化经验、原文定位及必要来源字段；保存、保存中、保存失败和重试均有实际反馈。
3. 草稿列表和已发布列表有明确状态，预览呈现教师最终阅读效果。
4. 发布前按已确认规则检查必填信息、原文关联与人工确认状态，提示发布后的可见范围。
5. 修改已发布案例进入独立修订草稿，未发布修改不能提前影响教师检索和学生指导。
6. 修订发布后，新检索与新指导采用当前有效版本；已经发布的教学任务和历史指导继续保留其版本、材料与内容快照。
7. 处理旧 `TeachingCase`、旧接口和聚合 `/api/platform` 的兼容路径，避免旧自动保存把已发布正文覆盖。旧案例缺少材料定位时如实显示，不补造原文来源。
8. 撤回、归档或删除按访谈确认的规则实现，保留必要后果提示和既有引用的可解释性。

数据表与字段根据工程规模设计，不预设一套必须照搬的复杂架构。需要迁移时编写实际 MySQL 迁移并验证旧数据兼容，不重建现有数据库代替升级。

### 八、接通教师、备课和学生指导

本步不能只交付孤立的材料管理页面。

- 新发布案例能被既有 BM25 检索到；标题、正文和需要纳入检索的结构化字段保持一致，草稿不进入正常检索。
- 教师检索与阅读能看到实际案例正文、来源、适用信息和关键原文位置，点击后能到对应材料。
- “用于备课”带入当前选定版本的教学内容，允许教师继续编辑，不破坏原教案其他活动。
- 学生指导能读取相关发布内容及必要教学经验；教师回看对应指导时能够确认使用了哪一版材料快照。
- 正常学生界面围绕学习指导呈现；材料出处和核对范围使用必要的展开区域或 tooltip，不堆放管理说明。
- 修订、发布与撤回后，列表、详情、检索、备课和指导的行为符合已确认版本规则。仅重新加载列表或显示发布提示不能替代实际数据联动。

### 九、桌面页面与文案

保持现有 Nova、shadcn-vue 和 Lucide 设计语言。主工作区优先采用材料列表 → 原文与编辑双栏 → 必要发布操作的清楚结构；分栏可调整，长文与页面滚动不会把保存、页码或关键操作挤出可操作区域。

- 检查 1440、1920、2560 宽度及浏览器缩放，控制行长、栏宽、信息密度和无意义的大片空白。
- 文字对比清楚，标题、正文、来源和主操作有明确层级，不用过浅颜色承载关键信息。
- 删除重复标签、口号、教学式帮助段落和冗余辅助文案，让布局和按钮解释操作；必要补充用 info＋tooltip。
- 保留表单标签、可访问名称、键盘焦点，以及发布、撤回、覆盖和删除的后果提示。
- 检查空材料库、空草稿、无搜索结果、加载、处理中、部分完成、保存失败、重试和无效详情链接。
- 不扩展手机端页面、移动导航或原生应用；不为填满空间伪造材料、作者或使用成效。

### 十、实际验收与交付

按用户确认的材料样本和范围实际走通：

管理端上传 → 保存原文件和来源 → 真正解析 → 处理进度可见 → 原文定位 → Codex 提取 → 人工修改并保存 → 刷新恢复 → 教师预览 → 发布 → BM25 检索 → 教师按 ID 阅读并查看原文 → 用于备课 → 学生指导关联发布内容。

继续验证：

- 文字材料与需要图文识别的材料分别走对应路径，至少有一次本步新增提取能力的真实 Codex 调用。
- 解析或提取中断后保留已完成片段；手动重试符合确认规则；失败不会把人工编辑清空。
- 多篇材料和案例互不覆盖；旧案例与旧任务仍可读取。
- 修订未发布不影响当前发布内容；发布新版本不改写旧任务和旧指导快照。
- 未匹配、无原文、无效 ID 和发布信息不完整等状态有可观察的正确结果。
- 真实 MySQL 读写、API 重启恢复、页面刷新、前进后退和直接打开详情。
