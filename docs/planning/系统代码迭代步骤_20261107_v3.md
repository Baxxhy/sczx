# 师承智学从零开发步骤

日期 2026-11-07　版本 v3

1. **确定平台结构和第一条完整使用流程。** 从零建立师承智学，划分学生端、教师端和项目管理端，错题帮作为学生端的独立子软件入口。围绕“优秀教学经验—教师备课—班级任务—学生学习—独立练习—教师反馈”组织全部模块，首个单元沿用一元一次方程，首课沿用等式性质。先明确三端页面、页面之间的跳转和每页主要操作，使后续开发围绕一条可实际完成的教学流程展开。

2. **先确定高质量的前端视觉与交互设计。** 建立完整的配色、字体、字号层级、留白、图标、插画、卡片、表单、图表和动效规范，形成有辨识度的教育产品风格。重点设计学生学习首页、课程学习工作区、错题帮、教师案例库、备课编辑器和班级学情页，让课程内容、数学公式和学习反馈具有清晰的阅读层次。完成电脑、平板、手机的页面方案，以及加载、空白、错误和完成状态，使整个使用过程保持统一的视觉质量。

3. **搭建前端工程并完成可点击的核心页面。** 使用 Vue 3、JavaScript、Vite、Vue Router、Pinia、shadcn-vue、Reka UI 和 Tailwind CSS，建立三端布局、公共组件和导航。先以明确标注的演示数据完成关键页面，走通从教师选案例到学生完成任务的页面跳转，检查真实屏幕上的排版、图文质量、公式显示和操作反馈。将课程卡片、案例阅读、题目作答、教案编辑和学习进度做成统一组件，后续逐页接入真实接口。

4. **建立简单可运行的后端与数据基础。** 使用一个模块化 FastAPI 业务服务连接 MySQL，将教学、检索和数学计算组织为清楚的 Python 模块，通过 API 适配器调用外部模型。建立账号、班级、课程、课时、案例、教案、任务、作答、错题和学习记录的数据结构，完成登录、文件保存、基础查询、数据初始化及版本更新。开发使用独立数据库，保留已有学生资料与数据库，先做到前端能够创建、保存并重新读取真实数据。

5. **接通统一模型能力和任务执行。** 按 ApiPoolProvider 的思路统一文本、图文/OCR、Embedding、Rerank、ASR 和 TTS 外部 API，完成配置、调用、结果解析与错误反馈。通过 Pydantic 约束模型输出，通过 SymPy 核对可计算的数学结果，提供后台任务、SSE 进度显示、超时处理和手动重试。先用实际请求完成图片识别、结构化讲解和检索向量生成，并将语音能力纳入同一接口体系。

6. **完成公开材料与教学案例管理。** 建设管理端的材料上传、文档解析、原文阅读、案例编辑和发布页面，保存作者、来源、适用学段和原文位置。通过图文 API 与结构化提取，将优秀教学经验整理为教学目标、学生困难、引入方法、讲解步骤、提问方式和回应后的调整策略，支持项目成员对照原文和数学结果修订。让教师能看到完整可读的案例，平台能调用其中的结构化经验。

7. **建设课程、知识关系和首课内容。** 完成课程目录、单元、课时、前置知识、学习目标、例题、活动和练习的编辑与发布，将每课关联到相应教学案例。录入等式性质首课的完整讲解、等式天平活动、随堂练习和独立检查题，准备教师教案素材及明确标注的演示班级。完成课程详情页和课时内容预览，使下一步的检索、备课和学习功能都能使用真实内容。

8. **建立能按教学情境查找经验的混合检索。** 采用 Embedding API、BM25、Qdrant 和 Rerank API，将语义检索、关键词检索、结果融合和重排序接成完整流程。材料同时保留细粒度片段与完整案例上下文，按知识点、教学目标、学生困难和年级筛选，支持内容发布后的索引更新。加入查询改写和必要的补充检索，让“学生不理解等式两边为什么要同时变化”能够找到相应讲法与原文依据。[Qdrant 混合查询文档](https://qdrant.tech/documentation/search/hybrid-queries/)

9. **建立面向教学任务的 Agent 编排。** 使用 LangGraph 组织规划、经验检索、教学生成和结果核验，按备课、答疑、练习生成等任务运行相关步骤。为各步骤配置结构化输入输出和工具调用，遇到缺少材料、数学不一致或学生补充信息时进入对应处理分支，支持教师修改生成结果。接入持久化检查点和过程记录，通过 MySQL 适配保存需要恢复的状态，让任务能够暂停、继续并查到使用过的案例。[LangGraph 持久化文档](https://docs.langchain.com/oss/python/langgraph/persistence)

10. **完成教师案例浏览与辅助备课工作区。** 教师能够按目标和学生困难搜索案例，阅读讲解、提问及调整方法，选择案例生成教案。备课页采用案例参考与教案编辑相邻的工作区，支持调整目标、讲解、例题、活动和练习，局部重新生成、保存版本、预览学生页面以及导出教案。完成从选择优秀经验到得到可直接用于教学的课时内容的全过程。

11. **完成班级、教学任务和师生消息。** 支持教师创建班级、邀请学生、查看成员，将课时、练习和截止时间发布为学习任务。学生首页显示待完成任务、教师反馈和继续学习入口，教师查看参与、进度和提交情况。将已发布内容与学生任务关联，支持补充任务、订正通知和学习提醒，使备课结果能够真正到达学生并产生学习记录。

12. **完成学生课程学习与多模态互动指导。** 建设以课程内容为主体的学习工作区，将讲解、例题、学习进度和答疑安排在清楚的布局中。支持文字提问、上传题图、请求提示、举例、换讲法、补基础和自己尝试，Agent 根据当前目标、检索到的案例及学生回应组织指导。逐步呈现公式、图文和学习活动，保存原提问、原作答及帮助记录，并支持暂停后继续。

13. **完成互动教具、练习与错题帮子软件。** 使用 VisualizationSpec 和固定前端组件实现等式天平等课内互动，记录学生操作与解释。完成随堂练习、独立新题、文字及手写作答、批阅、订正与再次尝试。借鉴原错题帮的使用思路，从零实现拍照录题、裁剪、OCR 修订、错因分析、分步补救和变式练习，支持课程错题转入错题帮，再返回原任务继续学习。

14. **完成学习记忆、个性化补救与复习。** 将目标掌握情况、原作答、常见错误、提示使用和独立完成情况组织成可追查的学习记录，结合前置知识关系安排补基础和复习。对话保留当前学习上下文，跨课时记忆按需要提取相关证据，教师和学生能够查看判断依据并纠正错误记录。学生端形成直观的学习进度、知识掌握展示和下一步任务，推荐结果能够直接进入对应课时或练习。

15. **完成教师学情反馈和管理端日常操作。** 教师通过清楚的班级总览、题目分析和学生详情查看完成情况、共同困难、原作答及独立练习表现，确认或修改系统反馈，发布补充讲解、订正和复习。管理端完成案例发布、内容修订、师生问题反馈和失败任务重试。将案例使用意见反馈到内容整理流程，使教师使用、学生学习和教学经验改进能够连续进行。

16. **打通首课并上线一个完整单元。** 在隔离环境实际完成内容发布、教师备课、班级任务、学生学习、互动练习、错题补救和教师反馈，检查数据保存、刷新继续、任务失败重试和模型输出。围绕案例匹配、数学正确性、学生独立完成情况及教师能否修改结果检查效果，修复影响使用的问题。随后补齐一元一次方程单元的其他课时与单元复习，部署首版网站，让完整师生流程可以实际使用。

17. **扩展语音、教具、组卷与考试。** 在首版可用后加入语音提问、识别文字修订、讲解朗读和播放控制，补充后续课时需要的互动教具。完成教师题库选题、智能组卷、试卷编辑、考试发布、学生答卷、批阅与讲评，以及教案、试卷和学习记录的批量导出。将这些能力接入已有课程、班级和学习记录，并统一其页面风格。

18. **扩展实时课堂、分层教学和教研交流。** 教师能够开启课堂、推送活动、查看即时作答和安排课后任务，根据学习记录调整学生分组并发布分层练习。增加案例与教案分享、收藏、讨论、改编和使用反馈，让新的教学经验进入整理发布流程。同步完善成长记录与知识关系展示，使课堂、课后学习和教师教研能够在平台内衔接。

19. **完成离线使用与全平台视觉精修。** 加入课时材料下载、离线阅读和作答保存、联网同步与继续学习，对依赖模型 API 的操作提供明确的联网状态反馈。以实际学习、备课和课堂页面逐屏调整排版、图片、公式、图表、动效与响应式布局，补齐长内容、空数据、加载和失败状态，检查所有主要按钮和跨页面操作。让首屏展示、长时间学习和日常教学都具有一致且精致的使用体验。

20. **完成最终部署、交付和实际使用走查。** 配置 CPU 环境中的网页、Python 服务、MySQL、Qdrant、模型 API 与文件存储，完成启动、更新和备份恢复。使用新账号从教师建班到学生完成整个单元走查一次，检查三端功能、错题帮入口、扩展模块及真实数据展示，修复阻断使用的问题。交付可访问的网站、安装与使用说明、明确标注的演示内容和演示视频，再依据项目成员及具备条件后的真实师生反馈持续改进。
