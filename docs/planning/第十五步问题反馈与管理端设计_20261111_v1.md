# 问题反馈与日常管理

2026-11-11，v1。

Issues.vue从单个store.data.issue改为GET /api/support多条队列，可搜索、筛选和查看历史。学生/教师侧栏均可进入；全局体验反馈写system类别。学生学习疑问必须选择本人已分配任务。

SupportIssue保留旧text/reply/resolved，增加task_id、category、status、revision、request_key及可空created_at。SupportIssueEvent记录操作者、UTC时间、旧/新状态及内容；旧回复单独回看，不伪造旧创建时间或历史事件。

状态为pending、processing、replied、closed。POST /support创建；POST /support/{id}/events处理，必须携带expectedRevision和请求键。并发用行锁与revision拒绝过期修改，重复请求不重复追加；输入在409后保留，可重新读取再提交。学生只补充或关闭本人问题；教师仅处理当前有权限班级且源任务属于自己的学习问题。无任务旧疑问按现有成员归属兼容读取。管理员仅看到system/content，不读取无关私人学习问题。

旧PUT /issues/{id}/reply转入同一审计流程；过期PUT /platform不再覆盖已有问题正文、回复及状态。已有问题不删除。

管理端按问题、模型、账号与运行分区，复用MaterialWorkbench、ModelConsole、AccountManager及LegacyImport。既有资料、来源、审核、发布、版本能力不重建，本步以真实上传/核对/修订/发布回归确认旧任务和安排引用未变。

GET /api/ai/failures提供类型、时间、执行/自动重试次数、原因、状态和是否可重试。管理员对他人业务任务只能查看最小异常元数据，不返回私人输入/输出；只有原提交账号可重试。教师本人及学生本人保留业务范围内的列表。

重试再次检查原账号、当前成员、实际任务归属、课时和选定案例版本、资料/原文片段；来源撤回或更改要求重新发起。沿用原ModelJob与运行编号，不复制业务数据。实际Codex gpt-6-luna/low重试成功记录见states.json，受控异常及权限另见MySQL测试。
