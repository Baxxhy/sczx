# 第十六步完整业务与评测报告

2026-11-11，v1。目标环境为本机生产构建预发布8087，FastAPI/MySQL/Codex CLI gpt-6-luna、low。正式日常入口仍为5177/8000；所有验收学生为新建的“单元验收”或“预发布冒烟”账号。

教师链：两个新教师、两个主要班级，每班初始至少3名学生，另有跨班学生s6、晚入s7和移出历史s8。管理员通过原资料→解析→案例审核→课时审核流程安装五课；教师实际浏览器检索、阅读案例，用真实Agent生成简单方程备课，修改目标，确认保存、学生预览并发布。其他课时沿用原保存/版本/发布API，两位教师各发布五课。没有自动把模型教案直接发布。[教师浏览器](../verification/unit_20261111_v1/teacher-browser.json)、[真实Agent](../verification/unit_20261111_v1/agent-initial.json)、[十项任务映射](../verification/unit_20261111_v1/tasks.json)。

学生链：s0从第一课阅读、操作天平、填写解释、练习和检查。简单方程进入前置课时复习并返回，实际求助；随后完成变形、应用和复习。每课刷新恢复，最终5/5提交；学习记忆含真实不同知识点事件。首轮浏览器脚本因目录同名文字提前匹配页面而停止，第二次保留已提交第一课后继续，未删除或重置原始错误；最终报告明确含resume。产品修复没有用修改答案或伪造完成补证。[学习记录](../verification/unit_20261111_v1/student-browser.json)、[前置跳转初段](../verification/unit_20261111_v1/student-browser-first-failure.json)、[实际操作日志](../verification/unit_20261111_v1/student-browser.log)。

模型链：五课各执行hint、example、rephrase、foundation、try、OCR和确认后指导，共35流程样例，其中try五条是程序检查点，不宣称调用模型；其余30条实际Codex请求通过。OCR原图是实际浏览器题目截图，原识别与核对后文本分别保存；确认动作由验收脚本对照自编原题执行，不当作人工OCR准确率标签。[输入输出与时间](../verification/unit_20261111_v1/model-unit.json)、[原题截图信息](../verification/unit_20261111_v1/question-images.json)。

补救与反馈链：s0在乘法、加法和乘加应用三类题答0，保存原题原答及解释。每题实际错因分析、确认、提示、生成练习与独立新题、用实际返回方程核验作答；全部retest_passed。第一次乘法错因的模型证据未逐字来自原答，被拒绝且未采用；另开请求明确只引用原答字符0后成功，原失败任务不删除。不是放宽证据规则，也不把原错误改对。[初次补救含失败](../verification/unit_20261111_v1/repair-unit.json)、[定向重试](../verification/unit_20261111_v1/repair-retry.json)。

教师查看应用题原始错误与数值待核对记录，发送订正安排，学生提交数量关系说明；说明提交本身不算独立成功。之后另外生成并核验新变式，干预结果才出现新增独立正确证据。教师保存反馈，学生重登读取；最终还在浏览器重新编辑反馈保存，学生重新登录回看。[师生反馈和多问题队列](../verification/unit_20261111_v1/feedback-flow.json)、[干预后的实际新题](../verification/unit_20261111_v1/search-intervention.json)、[终验浏览器](../verification/unit_20261111_v1/final-browser.json)。
