## 二、我发现的具体问题与待验风险

结合最新源码、三角色测试报告和实际页面截图，当前最值得检查的是以下五项。

| 优先级 | 位置 | 问题与判断 |
|--------|--------|--------|
| P1 待验 | `main.js`、`store.js` | 页面导航前会执行 `store.save()`。当前代码对已登录且数据就绪的路由切换都会尝试保存，保存失败时可能阻止用户进入其他功能。需要验证是否产生无意义请求，以及网络故障时的导航行为 |
| P2 | 教师备课 | 同时存在“AI备课”页签、页面快捷按钮和“AI改写此活动”。前两者可能重复；第三个有明确的单活动作用域，应保留并区分 |
| P2 | 管理员“管理与运行” | 从账号管理离开后重新进入，可能回到默认“问题反馈”分类，已在测试报告中确认 |

## 四、第二阶段：功能位置审查

这一阶段必须严格从真实用户的视角执行。

每名角色使用新的浏览器会话，从正常登录页面开始。

每个任务记录：

- 是否进入了错误页面。
- 是否需要返回。
- 是否出现多个同名按钮。
- 是否需要查找隐藏菜单。
- 是否能够确认任务已经完成。
- 是否可以返回原来的操作位置。

### 位置验收原则

1. 常用任务应该从所属业务入口自然找到。
2. 一般任务尽量在三级导航以内完成定位。
3. 页面名称应直接说明用户要做的事情。
4. 关键操作不能长期藏在“更多操作”中。
5. 低频高级功能允许使用弹窗或折叠。
6. 错误、保存状态和不可逆操作后果必须直接可见。
7. 不允许因为导航简化而造成实质功能不可达。
8. 跨页面返回应尽量保留当前班级、学生、试卷或任务上下文。

不得为了减少入口数量而损害用户操作效率。

## 六、第四阶段：重点技术风险复核

当前源码还有一处需要优先验证：

`frontend/src/main.js` 中的路由守卫，在已登录且数据就绪时会调用 `store.save()`。

`frontend/src/store.js` 的保存方法会执行平台数据写入。

请重点检查：

1. 没有数据变化时切换页面，是否仍执行无意义保存。
2. 连续快速切换五个页面是否产生重复写入。
3. 保存进行中切换页面是否正常。
4. 网络断开时能否进入原本可访问的只读页面。
5. 保存失败时未保存草稿是否得到保护。
6. 重试保存后是否可以继续导航。
7. 离线学习入口是否保持原有可用性。
8. 是否存在旧请求覆盖新状态。

如果确认有问题，采用最小改动的脏状态判断和保存保护机制。

不要为了简化跳转取消必要的草稿保存保护。

这次可以直接让 Codex 执行上述专项验收。**不需要再设计一轮新界面。**

验收完成后，真正值得留下的功能应满足以下要求：用户知道在哪里找、点击后能够完成任务、完成后结果可以保存和回看。能够满足这些要求的快捷入口可以保留；造成重复理解成本的入口应合并。

目前的模拟角色测试已经证明主要路径比上一版清晰，但**全量功能与入口的一一对应审查尚未完整形成证据**。这正是下一轮最值得投入的工作。
