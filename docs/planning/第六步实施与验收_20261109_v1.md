## 决策与依赖

第一轮：桌面 Web 的首课材料闭环；支持文字/扫描/混合 PDF、DOCX、PNG/JPEG；独立材料与多案例，作者未知如实留空。采用推荐。

第二轮（依赖格式与材料关系）：文件上限30MB，PDF最多30页，DOCX最多300个正文片段；按页/段落/表格/插图定位，不伪造Word页码；图片整图定位，本轮不做局部框选。材料解析与每页OCR分开任务，成功页面保留。采用推荐。

第三轮（依赖处理结果）：选择已完成片段提取教学经验；单次最多8片段/24000字，较长材料分批产生可编辑案例，再由管理员整理。结构化经验和原文摘录关联；模型只产生新草稿，不覆盖人工编辑。采用推荐。

第四轮（依赖案例生命周期）：草稿独立保存，人工核对后发布不可变版本；修改后重新核对；撤回退出新检索，已发布历史版本与原文仍可回看；不提供物理删除材料/历史版本。既有教学任务保留快照，新备课保存所选版本信息。采用推荐。

共同理解：上传原文→真实解析→按位置对照与修订→Codex提取→人工编辑→预览/发布→BM25→教师阅读原文与备课→学生指导关联版本和来源。用户的自动采用推荐指令作为本轮共同理解与执行授权，不冒充逐题人工回答或教师评审。

## 实施任务

1. 增加材料/片段、案例草稿/不可变发布版本及教案来源快照的MySQL迁移；迁移既有发布案例，不改写历史任务。
2. 复用文件、ModelJob、SSE及CLI，实现真实PDF/DOCX解析、逐页OCR、恢复和片段修订；新增专用Pydantic提取结构。
3. 建立多案例编辑、预览、人工确认、发布、修订和撤回，统一旧保存接口边界，避免聚合自动保存覆盖新版本。
4. 管理端材料列表与可调整原文/案例双栏；教师详情与原文定位；检索、备课与学生指导版本联动。
5. 隔离账号与数据验证各格式、真实CLI、失败重试、版本快照、刷新/重启；桌面1440/1920/2560截图和构建；完成使用说明并提交。
