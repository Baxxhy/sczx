# 二、阶段A：修复 Word 导出与 AI 教案质量

## A1. 当前问题

用户已经检查实际导出的 Word，确认以下问题：

1. 中文字体不符合要求。
2. 英文字体不符合要求。
3. 标题使用了彩色主题样式。
4. 页面排版不够规范。
5. 教学活动段落较长。
6. 原文引用重复较多。
7. 教案中包含明显的 AI 生成痕迹。
8. 出现“教师手写保留”“保留例题”等编辑过程用语。

这些问题必须实际修复。

## A2. Word 强制排版规范

所有导出的正式教案必须满足：

| 元素 | 规范 |
|---|---|
| 中文 | 宋体（SimSun） |
| 英文、数字 | Times New Roman |
| 文字颜色 | 纯黑 #000000 |
| 纸张 | A4 |
| 上下页边距 | 2.5cm |
| 左右页边距 | 2.7cm |
| 标题 | 宋体、18pt、加粗、居中 |
| 一级标题 | 宋体、14pt、加粗 |
| 二级标题 | 宋体、12pt、加粗 |
| 正文 | 宋体、12pt |
| 行距 | 1.35倍 |
| 页码 | 页脚居中 |

必须显式设置Word的：

- ascii
- hAnsi
- eastAsia
- cs

同时处理Normal、Title、Heading 1、Heading 2、列表、表格和页眉页脚样式。

不得遗留主题蓝色和默认Calibri/微软雅黑样式。

必须通过OOXML检查实际样式，不能仅依赖 `font.name`。

## A3. 正式教案结构

默认导出按以下结构组织：

1. 课时基本信息。
2. 教学目标。
3. 学情分析。
4. 教学重点与难点。
5. 教学过程。
6. 例题与练习。
7. 课堂评价。
8. 参考案例及材料出处。

已有字段正常导出。

没有数据的字段不编造内容。

教学过程优先呈现：

- 教学环节。
- 教师活动。
- 学生任务。
- 关键提问。
- 教师调整。

避免把教师活动、学生回应和调整建议堆在一整段中。

## A4. 严格修改AI生成语言

修改：

`backend-business/sczx_business/codex_provider.py`

重点修改 `lesson_plan` 的指令。

要求模型使用符合实际教学场景的语言。

必须做到：

- 一句话只描述必要的教学动作。
- 减少空泛目标。
- 不重复解释相同知识点。
- 不重复堆积“引导学生”“进一步追问”等句式。
- 提问应当有明确的教学作用。
- 教学活动应当有具体步骤。
- 教师建议应当能够直接执行。
- 不虚构真实学生反应。
- 不虚构课堂教学效果。
- 不改动现有数学参考答案。

正式教案正文不得出现：

- 教师手写保留。
- 保留例题。
- 原任务已保留。
- 根据用户要求。
- 模型生成内容。
- 当前任务上下文。
- 不增加题目ID。
- Agent执行完成。
- 已通过结构核验。

这些编辑及系统信息应保留在操作日志或界面状态中。

对于教师历史版本中已经存在的这些文字，不得未经确认自动删除；可以提出清理建议并提供人工确认。

## A5. 参考文献和材料引用

修改：

`backend-business/sczx_business/drafts.py`

默认正式教案只展示：

- 案例名称。
- 案例版本。
- 来源。
- 主要参考内容。
- 材料页码或定位。

删除导出视图中的重复引用，不删除数据库原始证据。

同一材料、位置和原文内容形成的重复引用，只展示一次。

支持：

1. 正式教案：精简来源。
2. 完整溯源版：保留必要的详细原文证据。

不能把自编验收材料包装成真实教学研究。

## A6. 生成质量验收

必须使用：

- 一个原有教案版本重新导出。
- 三种不同教学任务实际调用Codex生成。
- 新旧导出对比。

自动检查：

- 字体。
- 颜色。
- A4。
- 标题样式。
- 引用去重。
- DOCX可解析。
- 内容与选定版本一致。
- 没有引入新数学错误。

人工检查：

- 教学目标是否清楚。
- 教师活动是否可执行。
- 学生任务是否明确。
- 是否存在重复套话。
- 是否出现生成过程元话语。
- 参考资料是否适度。

如果可使用Word/WPS，必须打开、修改、保存、重开。

如果没有可用Office环境，保留该项为外部待验收，不得虚报。

# 三、阶段B：实施第十一步

第十一步主题：

**班级、教学任务与师生消息。**

不要重做现有教师备课、课程管理、Agent和学生学习界面。

需要在现有能力上补齐以下功能。

## B1. 多班级管理

支持：

1. 教师创建多个班级。
2. 编辑班级名称、年级和学科。
3. 学生加入班级。
4. 教师查看和管理班级成员。
5. 教师安全移除学生。
6. 学生可以属于多个班级。
7. 教师只能访问本人班级。
8. 学生只能访问有权限的班级。

优先实现有过期时间、可撤销、不可轻易猜测的邀请码。

不增加短信、邮件等外部服务依赖。

## B2. 修复多班级任务隔离

重点审查：

- Classroom.vue
- TaskList.vue
- Insights.vue
- store.js
- main.py

当前TaskList直接使用全局任务数据，需要改进。

确保：

- A班只显示A班任务。
- B班只显示B班任务。
- 不同教师的任务不会混淆。
- 切换班级后任务列表正确更新。
- 旧异步请求不能覆盖新的班级数据。
- 没有学生记录时不会产生前端异常。

教师端任务状态必须采用班级汇总。

学生端任务状态采用学生本人记录。

不得继续用一名学生的完成状态代表全班。

## B3. 任务管理

实现：

- 待开始。
- 学习中。
- 已提交。
- 已逾期。
- 已反馈。

教师可以：

- 查看班级任务。
- 查看已分配人数。
- 查看已开始人数。
- 查看已提交人数。
- 查看未完成人数。
- 查看逾期人数。
- 发送补充任务。
- 发送订正通知。
- 查看任务历史。

保留已发布任务快照。

补发任务必须幂等。

不能修改历史学生作答。

## B4. 师生消息

实现以下消息类型：

- 新任务提醒。
- 截止提醒。
- 逾期提醒。
- 教师反馈。
- 订正通知。
- 补充任务。

消息必须：

- 持久化。
- 具有发送者和接收者。
- 关联具体班级和任务。
- 支持已读/未读。
- 支持跳转相关任务。
- 刷新和重新登录后保留。
- 不重复发送。
- 不暴露其他学生的私人反馈。

优先采用MySQL + FastAPI已有架构。

不要引入WebSocket聊天室、Redis或新的微服务。

## B5. 教师和学生首页

教师首页显示真实的：

- 当前班级。
- 班级任务数。
- 未提交人数。
- 待反馈记录。
- 最近提交。

学生首页显示真实的：

- 待完成任务。
- 进行中任务。
- 任务截止时间。
- 新消息。
- 教师反馈。
- 继续学习入口。

禁止硬编码数量。

## B6. 多用户真实验收

至少准备隔离测试数据：

- 2名教师。
- 3个班级。
- 每班3名学生。
- 1名跨班学生。
- 1名后加入学生。
- 每班2项任务。
- 1项逾期任务。
- 1条补充任务。
- 1条订正消息。
- 1条教师反馈。

重点验证多班级隔离、权限及任务生命周期。
