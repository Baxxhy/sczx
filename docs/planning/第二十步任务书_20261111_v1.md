# 三、阶段A：正式部署工程整改

## A1. 解决自动迁移风险

当前 `deploy/manage.py` 在执行 `start` 时自动调用数据库迁移。

正式部署必须修改这一行为。

要求：

1. 将数据库迁移与服务启动拆分。
2. 提供独立迁移预检命令。
3. 提供迁移计划输出。
4. 明确当前版本和目标版本。
5. 对正式目标要求显式执行迁移操作。
6. 拒绝在未确认迁移状态时直接启动不兼容代码。
7. 迁移失败时禁止继续启动新版本。
8. 迁移操作不得自动清理或重建数据库。
9. 支持不产生副作用的预检模式。
10. 保留完整迁移日志。

正式库操作不能依赖隐含的 `start` 副作用。

## A2. 数据库版本迁移

正式库当前为0013。

必须在独立备份副本验证：

```text
0013
 ↓
0014_examinations
 ↓
0015_classroom_community
 ↓
0016_offline_drafts
```

验证内容包括：

- 迁移前所有现有表。
- 迁移后新增表。
- 原有记录数量。
- 关键业务记录摘要。
- 学生原始作答。
- 题库和考试记录。
- 班级成员关系。
- 模型任务和历史结果。
- 已发布案例和课程版本。
- 文件关联。
- 离线同步回执。

必须验证迁移后的业务代码能够正常读取原始数据。

不允许仅检查Alembic版本号就判定迁移成功。

## A3. 生产配置

创建明确的开发、预发布、正式环境配置规范。

需要包含：

- MySQL连接。
- 文件存储路径。
- Python运行环境。
- 前端构建路径。
- 服务监听地址。
- 公开访问地址。
- HTTPS。
- Cookie Secure属性。
- 反向代理信任配置。
- Codex CLI运行身份。
- 模型任务超时。
- 日志位置。
- 备份目录。
- 数据保留策略。

不得提交：

- `.env`
- Token
- Cookie
- SQL备份
- 登录凭据
- 学生私人数据
- 浏览器用户配置目录

公网部署必须使用HTTPS。

验证HTTPS下的认证Cookie、Service Worker、IndexedDB及离线学习正常工作。

## A4. 长期运行保障

需要提供可长期运行的服务配置。

优先考虑现有Linux环境中的systemd。

实现：

- 开机启动。
- 异常退出后恢复。
- 服务运行状态查询。
- 停止与重启。
- 日志查看。
- 持久化目录。
- 服务账户权限。
- 启动失败反馈。

服务必须使用固定的、已经验收的代码版本和前端构建产物。

不能继续依赖 `/tmp` 作为长期数据库、上传和构建目录。

必须验证宿主重启后服务能够重新启动，并保留已保存数据。

## C1. 教师完整流程

教师登录 → 创建班级 → 邀请学生 → 查找教学案例 → Agent辅助备课 → 修改教案 → 学生预览 → 保存版本 → 发布课时 → 查看学生学习 → 查看学情 → 发布补充学习 → 查看新作答 → 发送反馈。

每一步必须产生真实数据库记录。

## C2. 学生完整流程

学生加入班级 → 查看课时 → 学习完整单元 → 使用互动教具 → 文字或题图提问 → 独立作答 → 提交 → 产生错题 → 完成补救 → 独立复测 → 查看学习记忆 → 查看教师反馈。

必须检查跨课时记录关联。

## C3. 考试完整流程

教师题库选题 → 智能组卷 → 审核 → 发布考试 → 学生填写草稿 → 提交 → 程序核验 → 教师人工批阅 → 发布成绩 → 学生查看讲评 → 考试错题进入补救。

必须检查成绩及答案公开边界。

## C4. 实时课堂与分层教学

教师开始课堂 → 推送问题 → 学生实时提交 → 教师查看人数 → 结束课堂 → 保存历史 → 查看学习证据 → 分组 → 发布分层练习 → 学生完成 → 教师查看后续表现。

不得使用模拟提交人数冒充真实课堂统计。

## C5. 离线学习

学生下载授权课时 → 断网 → 重启浏览器 → 解锁并阅读 → 保存草稿 → 恢复网络 → 检查身份与版本 → 同步 → 继续在线学习 → 正式提交。

必须验证数据没有重复写入或静默覆盖。

## C6. 管理员流程

管理员登录 → 上传教学材料 → 解析 → 核对来源 → 编辑案例 → 审核发布 → 查看问题反馈 → 查看模型任务异常 → 执行允许的管理操作。

所有操作必须符合现有权限。
