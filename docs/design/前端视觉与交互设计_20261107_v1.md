# 师承智学前端视觉与交互设计

日期 2026-11-07　版本 v1

## 1. 本轮成果与使用方式

本轮对应从零开发计划第 2 步。交付本地可点击高保真原型，覆盖学生、教师和管理三端的七组核心页面，使用预设演示内容与浏览器本地保存。模型生成、班级发布及案例发布采用模拟交互。真实账号、数据库、模型与文件上传在后续工程步骤接入。

原型入口为 [index.html](prototype_20261107_v1/index.html)。可直接用浏览器打开，也可在项目目录启动静态服务。

```bash
python -m http.server 5176 --bind 127.0.0.1 --directory docs/design/prototype_20261107_v1
```

随后访问 `http://127.0.0.1:5176`。左侧“演示身份”切换三端，窄屏通过“菜单”展开。底部可重置本地演示进度。文件协议下的浏览器本地保存行为可能不同，推荐通过上述 HTTP 方式查看。

## 2. 视觉选择与技能使用

采用浅色编辑式工作区，以中性色层次组织页面，用青绿色表达学习进度与适当的状态，用中文宋体突出教学问题与案例阅读。这个方向由本轮设计判断确定，待用户视觉验收。

|技能|本轮采用的指导与实际应用|
|---|---|
|design-taste-frontend|运行应用界面方向抽取，选择 editorial-greeting，seed 1801089848；采用浅色开放侧栏、平面层次、同网格对齐及截图检查|
|ui-ux-pro-max|运行教育工作区设计系统检索，检查推荐适用性；参考按钮反馈、可见标签、焦点、44px 操作尺寸和响应式规则|
|frontend-design|沿用已读取的字体、内容纪律与风格一致性指导；在本阶段以工作区可读性统一三端|
|information-architect|使用第 1 步已确定的信息架构，保留角色入口、课程上下文和错题返回路径|
|verification-before-completion|用现有 Chromium 实际渲染、截图、走查，再按观察到的结果修订|
|Sites|阅读本地预览流程，使用项目内静态原型与本地浏览器查看方式|

设计系统检索初次返回偏儿童应用的立体风格及营销结构，与本项目初中学习、长文阅读和备课编辑的场景匹配不足，因此采用应用界面方向作为主设计依据。采用项目中文 Noto 字体，拉丁和数字跟随同一字体。未将技能里的多套视觉风格叠加。

平台特征落实在两处。学生用“等式两边共同变化”的问题和天平进入学习，教师用“教学安排与对应学生内容”并列进行备课。操作名称使用师生熟悉的“继续学习”“用于备课”“学生预览”“查看过程”。

## 4. 七组重点页面

|页面组|原型入口|主要设计与操作|
|---|---|---|
|学生学习首页|`#home`|继续学习为首要操作，搭配教师任务、复习与课程入口|
|学习工作区|`#learn`、`#check`、`#result`|观察天平、保存解释、举例和换讲法、提问、独立检查、求助后换题及查看结果|
|错题帮|`#wrong`、`#repair`|原题与原作答、录题弹窗、补救讲解、变式作答、返回来源任务|
|案例库与阅读|`#cases`、`#case-detail`|按关键词查找示例案例，阅读适用困难、教学步骤及来源说明，进入备课|
|备课工作区|`#prepare`|教师教案与配套学生内容并列，局部模拟生成、编辑保存、预览及选择班级发布|
|班级与学情|`#teacher`、`#class`、`#insights`|班级任务、三名演示学生的进度与帮助、查看过程、编辑反馈、安排补充学习|
|内容管理|`#manage`、`#content`、`#issues`|原材料与经验对照、来源登记、模拟核对发布、课程目录入口、反馈与任务重试|

辅助入口包含 `#courses` 课程单元与 `#records` 学习记录。`#content` 当前复用课时目录结构，完整课程编辑操作在对应工程阶段补齐。

## 5. 内容与数学示例

所有班级、学生、任务进度与学情统计均为演示数据。班级人数、已提交数与新题独立完成数从同一组演示学生数据计算。教师演示学生过程与当前用户本地练习记录分别标明其性质。

案例采用团队编写的结构示例，说明真实公开来源将在内容整理阶段登记。当前文案演示观察、预测、操作、等式表达与根据回应调整讲法的教学过程。

|例题|计算结果|用途|
|---|---|---|
|x − 3 = 5|两边加 3，x = 8|第一道独立检查|
|y + 4 = 11|两边减 4，y = 7|求助后换题|
|x + 3 = 8|两边减 3，x = 5|错题原作答与补救|
|z + 2 = 9|两边减 2，z = 7|补救后的变式|

天平展示 x = 5 及两边同时加相同数的关系。原型数值检查采用明确答案匹配，解释文字留给教师查看。正式批阅将接入数学核验及结构化处理。

## 6. 关键交互与状态

|路径或状态|原型行为|
|---|---|
|教师备课发布|案例进入备课，编辑后保存；打开学生预览，选班级模拟发布；班级与学生首页显示发布标记|
|学生学习|操作天平、保存解释；请求预设帮助；进入独立检查并提交结果|
|求助后换题|当前题保存帮助标记；切换到下一题时单独记录新尝试；新题作答依据当次帮助情况标记|
|错题补救|从课程结果进入补救，对照原作答并尝试变式，再回到原任务|
|教师反馈|编辑保存后，学生结果页读取相同的本地反馈内容|
|案例发布|更新本地案例发布状态并反馈模拟结果|
|加载|备课局部模拟生成时短暂禁用编辑区并显示生成状态|
|空内容|没有学习检查记录时，显示继续学习入口；案例关键词无结果时给出查找建议|
|失败|反馈与运行页展示模拟失败任务，支持重试；本地保存失败提示当前浏览器保存问题|
|题目不足|两道演示检查题使用完后提示保存或复习，保留已有记录|
|恢复|教案文本、学生解释、帮助、检查结果及反馈保存于浏览器本地；重进可回看|

录题与课程内容仍使用固定演示题，文件选择属于本地控件演示。自定义题目进入真实识别、内容逐块联动生成与全量字段保存将在后续开发步骤接入。原型中角色切换用于验收不同界面。

## 7. 多屏表现与验证

实际使用现有 Chromium 检查 1440px、768px、390px 三种宽度。1440px 保留固定侧栏与多列内容，768px 折叠侧栏保留适合阅读的分栏，390px 使用单列与菜单。表格在自身区域横向查看，公式区域可独立横向阅读。

|检查|结果与范围|
|---|---|

|控制台|浏览器走查期间无脚本异常|

## 8. 第 3 步工程衔接

第 3 步使用 Vue 3、TypeScript、Vue Router、Pinia、Reka UI 和 Tailwind CSS 建立正式前端。以当前高保真页面为视觉输入，将原型中的数据、视图和事件逐步映射到明确组件及状态。

|可复用输入|建议工程承接|
|---|---|
|CSS 变量及网格|主题变量、布局与响应式规范|
|角色导航、面包屑与移动菜单|三端应用布局和路由配置|
|内容面板、列表、标签与操作组|公共组件|
|教案和配套学生预览|备课区块、来源引用、学生内容预览组件|
|公式、天平、检查和补救|教学活动组件及固定 VisualizationSpec 渲染入口|
|帮助与尝试记录|当前学习会话状态和后端接口对象|
|弹窗、消息、保存状态|统一交互反馈与发布表单|
|演示数据|明确标注的数据适配层，后续接入真实业务接口|

下一步先按用户对视觉的反馈调整方向，再将已确认页面整理进正式工程。需要验收的选择为整体浅色编辑风格、中文字体层级、主辅区块比例，以及移动端采用单列学习内容的方式。
