# 启动、停止与更新

## 常用命令

使用固定Python执行：

python deploy/manage.py preflight --env 私有配置
python deploy/manage.py check --env 私有配置
python deploy/manage.py migrate --env 私有配置 --expected-current 当前版本 --target 目标版本 --log 持久迁移日志
python deploy/manage.py start --env 私有配置
python deploy/manage.py status --env 私有配置
python deploy/manage.py stop --env 私有配置

preflight只读，不建目录、不改表；输出当前版本、目标计划、写入者、连接、未结束任务和配置问题。check拒绝不兼容schema、缺失构建或不可用上传目录。start无隐式迁移；失败保留日志。

## systemd

deploy/sczx.service是正式模板，需按实际账户、Python、运维工具和环境文件路径修改后验证。ExecStartPre检查，ExecStart用serve前台运行，Restart=on-failure。正式首次启动先按批准执行activate，绑定该提交、数据库、公开URL和目录；之后同一配置自动恢复不需要重新签批准记录。换版本或目标需要重新批准和激活。

systemctl status 单元；journalctl -u 单元；systemctl stop/start/restart 单元。启用开机启动及宿主重启须在目标机器获准后执行。当前只实测临时预发布单元进程被终止后的恢复，不代表宿主重启验收。

## 更新顺序

冻结写入→停服务及其他写入者→预检→完整备份并验证恢复→显式逐目标迁移→检查固定包→按批准激活→启动→HTTPS登录、业务、离线与健康验收。失败时保留新库和上传，不直接降级或覆盖；按备份恢复手册在新库恢复配套旧版本，再批准切换。

## 日志与保留

迁移日志保留每次执行；服务日志放SCZX_LOG_DIR，systemd使用journal。建议每日备份，保留最近7份日备份和4份周备份；升级前备份及对应发布包单独保留。此为运维建议，不自动清理。用户资料、上传、已发布版本和数据库不随日志轮转删除。实施清理前核实范围及授权。
