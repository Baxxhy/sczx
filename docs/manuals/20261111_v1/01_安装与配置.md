# 安装与配置

适用版本：固定发布提交f985287324a93dd4902feec2f8dc9211803a0265。Vue 3＋JavaScript、FastAPI、MySQL。网页端，建议桌面Chrome/Edge；浏览器语音受操作系统能力限制。

## 安装顺序

1. 准备Python 3.13、Node.js 24、MySQL 8、mysql/mysqldump、Git、Codex CLI。当前验收用现有CLI登录，模型gpt-6-luna、思考low；不部署本地模型。
2. 从GitHub取得明确SHA；通过deploy/build_frontend.py生成同源前端；通过deploy/manage.py package --revision 完整SHA --frontend 构建目录 --output 新发布目录生成固定包。源码提交以sczx仓库根为准，不使用父仓HEAD。
3. Python虚拟环境、MySQL数据、上传、日志、备份、发布包放持久目录。安装backend-business所列依赖，核对实际解释器。配置仅KEY=VALUE，不执行Shell；凭据文件0600。
4. 复制deploy/release.env.example；填写数据库、上传目录、固定Python、frontend/dist、独立状态目录、日志、备份、公开HTTPS地址、Secure Cookie、反向代理可信IP和运行身份。发布目录不可被业务写入。
5. 新空数据库使用显式migrate --expected-current base --target 具体版本 --log 日志；已有库先停写、完整备份与隔离恢复。start不会迁移或初始化。
6. 管理账号由安装者在独立数据库初始化；管理员页面创建教师/学生，教师建班邀请。不要把演示账号当正式账号。

## 模型运行身份

Codex必须由实际服务账户登录，SCZX_CODEX_BIN、SCZX_CODEX_HOME和SCZX_RUNTIME_PATH指向该账户实际环境。先做最小请求，再做教学调用。预发布发现CLI默认去掉代理后连接超时；确需终端现有代理时，在私有环境文件显式设置SCZX_CODEX_INHERIT_PROXY=true并传递所需HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY。代理地址不提交仓库。不使用备用OPENAI_API_KEY。

文本、OCR、备课、补救通过CLI；检索使用本地程序算法。CLI不冒充Embedding、ASR或TTS服务。原生浏览器语音两项验收仍属环境例外。

## 环境区分

开发使用development.env.example；隔离预发布使用staging.env.example和sczx_test_库。正式使用production配置、固定发布清单和独立批准记录。当前9443只是回环自签TLS验证，不是正式域名或公网入口。正式目标尚待确定。
