# 三角色模拟 UI 评审协议

2026-11-12，初始版本3f64e01。模拟学生、教师、管理员各自使用全新浏览器配置，从登录开始用界面实际点击完成任务。测试实例8102；8099的qmx学习数据不作为试验对象。

这不是招募真人研究，不编造参与者引述、情绪或教学效果。观察到的点击、返回、错误与计算样式和评审推断分开记录。角色可以在同一工程测试实例写入明确的合成记录。

## 固定评分

| 类别 | 满分 | 固定扣分规则 |
|---|---:|---|
| 任务完成 | 30 | 六任务各5；直接完成5，一次绕路4，需要额外指路3，阻断0 |
| 导航位置 | 25 | 五项各5：分组明确、无重复混淆、子功能可找、返回上下文、主次清晰；每轻问题扣1、显著问题扣2、阻断0 |
| 信息主次 | 20 | 四个典型视图各5；每个冗余项扣1、严重堆叠扣2 |
| 字体 | 15 | UI同字族5、正文层级一致5、数学与界面协调5；据实按轻问题扣1、显著问题扣2 |
| 反馈与键盘 | 10 | 保存/失败反馈5，焦点与键盘5；据实扣分 |

本轮在第一次评分前冻结此规则，不为达到95修改权重、删除失败任务或隐瞒问题。同一个问题在不同类别造成独立后果时可以分别扣分，但必须说明依据。

学生任务包括学习作答、求助、错题复习、历史记录、考试课堂班级、离线与反馈；教师包括案例备课、预览发布、班级作答反馈、题库考试及教学扩展；管理员包括材料、案例、课程、问题、账号与模型任务。

## 迭代顺序

1. 三角色独立走流程、保存baseline报告及扣分依据。
2. 主代理形成问题清单，依据实际问题调整位置、导航与字体。
3. 角色使用同一任务与同一评分规则，重新从登录点击；记录修复与残留。
4. 如任一角色不足95，继续修复具体问题并复测，不直接调整分数。
5. 达到阈值后核对浏览器回归、构建、真实运行入口和GitHub推送。分数只表示该固定协议下的模拟评审结果。


## 版本与证据分层

- 基线：远程3f64e01的静态前端；8102在三份基线结束前未更新。
- 首次返修复测：`index-BxirpJC8.js` / `index-BRBChled.css`。三种角色使用新浏览器档案，从可见入口点击。
- 追加整改：首轮复测发现独立题计数不一致，主代理在桌面截图发现同名任务缺少发布时间；完成两项后仅重测受影响场景，保留其余有效证据。
- `layout/report.json`的33页×3宽度检查是技术检查，允许直接打开路由；不替代三角色以入口寻路的18个任务。
- 浏览器自动回归使用隔离内存数据；三角色使用8102独立MySQL的合成资料和新作答。8099/qmx的学习数据不参与写入测试。
