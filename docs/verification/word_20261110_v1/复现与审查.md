## 自动化命令

项目根目录，安装已有依赖后：

```bash
PYTHONPATH=backend-business python -m unittest discover -s backend-business/tests -v
PYTHONPATH=backend-business python -m unittest discover -s backend-business/tests -p test_docx_export.py -v
python -m compileall -q backend-business/sczx_business
npm --prefix frontend run test:unit
npm --prefix frontend run build
CHROME_PATH=/path/to/existing/chromium npm --prefix frontend test
git diff --check
```

MySQL完整套件另设SCZX_RUN_MYSQL_TESTS=1及独立sczx_test_*的SCZX_DATABASE_URL。测试拒绝业务库名；完整起止、库名和返回码见mysql-tests.json，不删除测试库。无MySQL的15项显式跳过不能计为通过。

## 实际导出与生成

教师登录后，历史教案v12通过 /api/preparation/lesson-equation/versions 选择固定版本，再GET export-options读取编辑标记。导出参数mode=formal或trace；cleanEditorial默认false，只有明确确认后为true。实际用户同意清理副本。original-protection.json记录该历史快照前后相等，数据库原文不变。

三类真实输入与时间见real-jobs.json。使用现有Codex CLI gpt-6-luna/low，每个任务的请求、六步过程、依据、输出、数学及文本报告见agent-activity/misconception/foundation.json。三份DOCX样例仅从对应plan与原课时题目组成内存副本，标注“生成样例，待教师确认”，没有写入正式草稿或发布。

实际浏览器完成正式/溯源下载、清理默认关闭、显式选择、质量警告→一次定向改进→局部再生成、差异窗口查看并关闭。其他块深比较一致，原草稿目标/活动与任务数量不变。第一次原生click未触发Reka下拉，改为实际指针点击后通过；browser.log保留初次等待超时，未因此修改产品。

## 渲染与字体

本机原系统Office仍不能启动，复用已有隔离运行时LibreOffice25.2.7.2，无系统重装。通用复现命令：

```bash
soffice -env:UserInstallation=file:///tmp/sczx-word-own-profile --headless --convert-to pdf --outdir /tmp/sczx-word-output document.docx
```

运行机使用 /tmp/lo_new/root/opt/libreoffice25.2/program/soffice。字体由fc-match确认SimSun和Times New Roman已存在。ooxml-audit.json检查四种字体属性、主题覆盖、黑色及文档结构；render-audit.json来自真实PDF逐页文本字形、颜色、边界及绘图扫描。全部19页截图位于docs/design/word_20261110_v1，页面索引逐一链接。

本地实际编辑验证使用独立本机UNO接口：打开正式DOCX，在临时副本插入验证段落，另存DOCX、关闭、重开读取，原文件SHA256不变，见office-edit.json。该验证未伪装成Word/WPS。

## 人工复核口径

用户明确同意仅清理导出样例前缀，认可三份PDF的表达风格，并确认新版Word/WPS显示、编辑保存及重开成功。完整原话记录在user-review.json；用户未指定软件品牌版本，不推断。风格认可不代表数学专家评审或课堂效果试验。

代理逐段检查19页的标题/正文/数学/出处/页码与分页；18个原题方程另做程序求解并核对保存答案，见question-math-check.json。条件与多变量关系仍保留教师核对机制。
